# palamedes2-like 基本動作検証版 v0.1.0（2026-10-18）

パラメデス２風・640×360・16bit風のブラウザ対戦パズルの**基本動作検証版**です。
確定済みのゲームロジックと表示・アニメーションを、納品済みの仮スプライトシート7枚で動かします。

> **対戦完成版ではありません。** 攻撃量の算式・役宣言による消去・勝敗（G01〜G06）は未確定のため実装していません。
> 未確定項目に対する検証版の暫定的な扱いは下の「未確定事項の扱い」と、ゲーム中の F1/H（操作説明）に明示しています。

## 動作環境

| 項目 | 内容 |
|---|---|
| 実行 | Chromium系（Chrome/Edge）・Firefox の最新版を想定。ローカルHTTPサーバー経由で開く |
| 開発 | Node.js 20.19 以上（検証は 22.22.0）、npm 10 系（検証は 10.9.4） |
| OS | Windows を基本想定。npm スクリプトはOS依存のシェル構文を使っていない（検証はLinux上で実施） |

## セットアップと起動（開発用）

```bash
cd palamedes2-like
npm ci                # package-lock.json どおりに依存を導入
npm run dev           # 開発サーバー http://127.0.0.1:5173/  （停止: Ctrl+C）
```

| コマンド | 内容 |
|---|---|
| `npm run typecheck` | TypeScript 型検査（tsc --noEmit） |
| `npm test` | 自動テスト（Vitest、ロジック・データ・タイミング 66件） |
| `npm run build` | 型検査＋本番ビルド → `dist/` |
| `npm run preview` | ビルド結果を http://127.0.0.1:4173/ で確認 |
| `npm run serve:dist` | 依存なしサーバーで `dist/` を http://127.0.0.1:8080/ に配信 |
| `npm run e2e` | ブラウザ実機確認（要ビルド済み dist、Chromium）。結果は `test-results/e2e/` |
| `npm run verify` | 型検査→テスト→ビルド→ブラウザ確認を一括実行 |

ブラウザ確認（e2e）は `playwright-core` を使います。Chromium が無い環境では一度だけ
`npx playwright-core install chromium` を実行してください。

## ビルド済み実行版の起動

`dist/`（配布ZIP・共有フォルダではプレイ版フォルダ）を HTTP で配信して開きます。HTMLのダブルクリック（file://）では
素材のJSON読込がブラウザに拒否されるため動きません。

- Windows：`start-windows.bat` をダブルクリック → ブラウザで http://127.0.0.1:8080/ を開く（Node.js が必要）
- 共通：`node serve.mjs . 8080`（停止は Ctrl+C）
- Node.js が無い場合：Python があれば `python -m http.server 8080 --bind 127.0.0.1`

URL に `?seed=数値` を付けると同じ乱数列（初期盤面・生成ピース）で再現できます。

## 操作（検証用のテスト設定。正式なキー割当は未確定 G06）

| 操作 | 1P | 2P |
|---|---|---|
| 左右移動 | A / D | ← / → |
| 打ち上げ | W | ↑ |
| B列入れ替え | S | ↓ |
| 役宣言 | Q | / またはテンキーEnter |
| 手動上昇 | E | . またはテンキー0 |

共通：F1またはH＝操作説明、R＝最初から、P＝一時停止、V＝素材確認画面（←→でページ切替）
検証用注入：1/2＝1Pへ攻撃+1/+10、9/0＝2Pへ攻撃+10/+1（攻撃量算式が未確定のため、通常プレイでは攻撃は発生しません）

キー割当は `src/input/controller.ts` の `DEFAULT_BINDINGS` で変更できます。

## 実装済み（確定仕様）

- ロジック（`src/core`、表示に依存しない・固定ステップ60tick/秒）
  - 24種ピース・原則均等生成・乱数差替え可能、MATCH初期配置 下側3段18個
  - 盤面・列・ピースID・移動中ピース・予約空白・共通基準を分離管理
  - 発射時は列を詰めず予約。到達時に成功判定（数字一致／隣接（1↔6含む）／属性一致）→ 基準SNAP更新・役ストック追加・予約解除・上詰め
  - 同一tick到達は1P優先、2Pは更新後の基準で判定
  - 失敗帰還（予約保持・帰還待ち列のみ発射/B禁止、他列と相手は継続）、B循環
  - 役ストック6個・7個目で最古破棄、4/5/6個の部分集合評価、同一部分集合で数字役/属性役、最強属性1種、属性役単独有効、複合翻数加算（二重加算なし）、宣言で全消費、宣言者のみ操作ロック
  - 攻撃ストック0〜29飽和、1波最大3ライン、攻撃による盤面は6段まで・入りきらない分は保持、被攻撃者の宣言演出中はWAIT
  - 自然/手動上昇（32px TWEEN）・手動は7段まで・宣言側は演出中に自然上昇停止、攻撃行追加はSNAP
  - 相殺の確定部分（相殺力＝通常攻撃力×2、余剰は攻撃へ転用しない）は関数とテストのみ（G01確定まで対戦フロー未接続）
- 表示（`src/view`）
  - 論理640×360、整数倍拡大・ドットを滲ませない、マニフェストから切出し、予備透明枠を通常アニメーションに含めない
  - キャラ左右TWEEN・FRAME、距離に依存しない同一所要時間の直線打ち上げ、成功後上詰め
  - 失敗：反発→高速山なり→元列X（Y76）→低速垂直下降（開始/終了時刻固定・最新予約位置へ追従）→SNAP
  - B：最上段を暗色で通常ピースの背面経由で最下段へ。キャラは攻撃枠1枚（attack_01）を一瞬表示、座標不変
  - 攻撃アイコン大2・小は左5→右4、起点/間隔は画面JSONどおり
  - 描画順（Z）は画面JSONの値どおり。役名16種×A/B/C色替え、背面光55・前面光65
  - 素材確認画面（V）：S1〜S3主要モーション、役名16×3、S4通常/小型/暗色、S5・S6全矩形、攻撃表示0〜29
- 入力（`src/input`）：1P/2P別系統。CPUは `Controller` を実装して後から接続できる（戦略は未確定のため未実装）

## 未確定事項の扱い（暫定。正式仕様ではない）

| 項目 | 検証版の扱い |
|---|---|
| G04 同一プレイヤーの複数発射 | 自分の打ち上げ中ピースが到達するまで次の発射を受け付けない |
| G04 空列への操作 | 発射・Bを受け付けない |
| G04 列移動中の追加入力 | キャラ移動TWEEN中の入力を受け付けない |
| G04 列アニメ中の再入力 | 上詰め・B入替TWEEN中のその列の発射・Bを受け付けない |
| G04 無役・同点役の宣言 | 実行せずストックを保持し、画面に通知 |
| G01/G02 役宣言の効果 | ストック全消費・役名演出・宣言者ロックのみ。攻撃量・消去なし |
| G03 8段到達・敗北 | 7段で自然上昇を保留し表示のみ。敗北・ラウンド終了なし |
| G06 勝敗・先取・CPU | 未実装（入力窓口のみ） |

アニメーション時間などのテスト用初期値は `src/core/config.ts`（`DEFAULT_CONFIG` / `DEFAULT_VIEW_CONFIG`）に集約しています。

## フォルダ構成

```text
palamedes2-like/
  docs/reference/  取得した仕様・JSON/CSVの読取り用コピー（原本は共有Drive）
  docs/            環境記録・技術選定・テスト結果・残課題
  public/assets/sprites/  仮PNG7枚（原本のまま、SHA-256照合済み）
  public/data/     sprite_manifest_v2.json / screen_layout_v2.json（原本のまま）
  src/core/        表示非依存のロジック（ルール・盤面・役・攻撃・固定ステップ）
  src/input/       1P/2P・将来CPUの入力窓口
  src/view/        描画・補間・スプライト再生・素材確認画面
  tests/           自動テスト
  scripts/         配信サーバー・ブラウザ確認・結果一覧生成
```

画像差し替え時は `public/assets/sprites/*.png` と `public/data/sprite_manifest_v2.json` を差し替えるだけで、ロジックは変更しません。
