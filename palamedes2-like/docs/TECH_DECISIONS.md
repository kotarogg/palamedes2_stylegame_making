# 技術選定と設計上の解釈（2026-10-18、v0.2.0 で更新）

## 技術選定

**TypeScript ＋ Vite ＋ Canvas 2D（独自の小さな描画層）＋ Vitest**。Phaser は採用しなかった。

理由：
1. 仕様の中心は「ロジックの論理時刻で成否・順序が確定し、描画は補間するだけ」（到達順・1P優先・帰還下降の固定時間・FPS非依存）。Phaser の Scene/Tween はフレーム駆動で、論理時刻からの補間と二重管理になりやすい。
2. 描画要素は矩形切出しとZ順の重ね合わせのみで、物理・シーン管理は不要。Canvas 2D で十分かつ依存が最小（実行時依存0）。
3. 640×360の整数倍拡大・`imageSmoothingEnabled=false`・CSS `image-rendering: pixelated` でドットを滲ませない制御が直接できる。
4. ロジックを Node 上で高速に自動テストできる（DOM不要）。

Vite はビルド・開発サーバー、Vitest は同じ設定でテスト。ブラウザ確認は playwright-core（実行時依存ではない）。

## 構造

- `src/core`：固定ステップ（60tick/秒）のゲームロジック。入力はtick単位のコマンド、出力は状態とイベント列。描画へ依存しない。
- `src/view`：イベント列を読み、論理時刻＋補間率で座標を計算して描画（ロジックへ書き戻さない）。
- `src/input`：1P/2P別系統の `Controller`。CPU は同じ窓口に後から追加できる。
- 時間値は `src/core/config.ts` に集約（テスト用初期値）。ゲーム結果に関わる未確定ルールは設定値として埋めていない。

- 1ラウンド＝`Game`、先取制の試合＝`Match`（勝敗表示 → 決定入力 → 新しい `Game`）。

1tick内の処理順（v0.2.0）：
基準到達（到達tick昇順、同一tickは1P優先）→ 帰還完了 → 役処理フェーズの進行（攻撃送信は双方の相殺計算後にまとめて反映）
→ 入力（1P→2P、移動終了時の保持入力を先に処理）→ 役連鎖タイマー → 自然上昇・危険猶予 → 攻撃波 → 敗北判定（同一tickの両者敗北は引分け）。
到達を入力より先に処理するため、成功到達と同じtickの入力は上詰めの操作制限を受けます。

## 仕様の解釈と、2026-10-18 の回答による状態

| # | 内容 | 状態 |
|---|---|---|
| 1 | 盤面は「足場（キャラが立つ線）から各列が下へ吊り下がる」構造。最長列が盤面下端に接し、足場Y＝下端−32×最長列段数。上昇・攻撃行は各列の下へ追加 | 回答に記載なし → 維持。ライン消去（上側の横1ライン＝各列の最上段）もこの構造で実装 |
| 2 | 最長列が短くなると足場が1段下がる（上詰めと同時間のTWEEN） | 維持。ライン消去後は「足場・キャラだけが段数TWEEN、残ったピースは動かない」 |
