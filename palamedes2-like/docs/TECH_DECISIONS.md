# 技術選定と設計上の解釈（2026-10-18）

## 技術選定

**TypeScript ＋ Vite ＋ Canvas 2D（独自の小さな描画層）＋ Vitest**。Phaser は採用しなかった。

理由：
1. 仕様の中心は「ロジックの論理時刻で成否・順序が確定し、描画は補間するだけ」（到達順・1P優先・帰還下降の固定時間・FPS非依存）。Phaser の Scene/Tween はフレーム駆動で、論理時刻からの補間と二重管理になりやすい。
2. 描画要素は矩形切出しとZ順の重ね合わせのみで、物理・シーン管理は不要。Canvas 2D で十分かつ依存が最小（実行時依存0）。
3. 640×360の整数倍拡大・`imageSmoothingEnabled=false`・CSS `image-rendering: pixelated` でドットを滲ませない制御が直接できる。
4. ロジックを Node 上で高速に自動テストできる（DOM不要）。

Vite はビルド・開発サーバー、Vitest は同じ設定でテスト。ブラウザ確認は playwright-core（実行時依存ではない）。

## 構造

- `src/core`：固定ステップ（60tick/秒）のゲームロジック。入力はtick単位のコマンド、出力は状態とイベント列。描画へ依存しない。
- `src/view`：イベント列を読み、論理時刻＋補間率で座標を計算して描画（ロジックへ書き戻さない）。
- `src/input`：1P/2P別系統の `Controller`。CPU は同じ窓口に後から追加できる。
- 時間値は `src/core/config.ts` に集約（テスト用初期値）。ゲーム結果に関わる未確定ルールは設定値として埋めていない。

1tick内の処理順（技術的な順序。G04の同時イベント全順序を確定するものではない）：
入力（1P→2P）→ 基準到達（到達tick昇順、同一tickは1P優先）→ 帰還完了 → 宣言演出終了 → 自然上昇 → 攻撃波。

## 仕様の解釈（要確認として報告するもの）

| # | 内容 | 根拠・理由 |
|---|---|---|
| 1 | 盤面は「足場（キャラが立つ線）から各列が下へ吊り下がる」構造。最長列が盤面下端に接し、足場Y＝下端−32×最長列段数。上昇・攻撃行追加は各列の下へ1個ずつ追加 | 原作連続画像（打ち上げ成功・せり上がり）で、列が足場の下に上詰めされ短い列の下が空く様子を確認。「成功後は上詰め」「足元Y＝最高列上端」「7段で足場が盤面上端」と整合 |
| 2 | 最長列が短くなった場合（成功で上詰め）は足場が1段下がる（上詰めと同時間のTWEEN） | 「最高列が変化すると足元位置を再計算」。下がり方の演出は未規定のためTWEENを選択 |
| 3 | 6個の宣言は、6個全体で役が成立すればそれを優先（4個部分集合の方が翻数が高くても） | 「成立する6個役を優先し、なければ4個部分集合」の文言どおり。意図確認を推奨 |
| 4 | 同点役：最大翻数の候補が、役の種類（数字役・属性役・色・個数）の異なる組で複数ある場合のみ「同点」。同じ役が別部分集合で並ぶだけなら同点にしない | ストック全体を消費するため、同じ役なら結果が同一 |
| 5 | 攻撃の適用可能量 ＝ min(3, ストック, 6−最長列段数)。段数は予約空白を含む | 「最大3」「攻撃で7段目まで押し込まない・6段まで」 |
| 6 | 最初の攻撃波までの待ちは波間隔と同じ約2秒（設定値） | 未規定。`firstWaveDelayMs` で変更可 |
| 7 | 手動上昇は自然上昇タイマーをリセットしない | 未規定。別入力イベントとして管理 |
| 8 | 名称の決まっていない複合（例：フォーカード＋同色統一）は、数字役→属性役の順にロゴを表示 | 表示名のみの技術選択（翻数・判定には影響しない） |
| 9 | 役光（S6 role_glow）の表示位置は役名枠の中心に合わせ、4個役は96×48、6個役は144×48を使用 | 役光表示高さは未確定一覧にあるため仮配置 |
| 10 | 山なり曲線の到達点Y=76はピース左上のY、山の高さは36px（設定値） | 画面設計の暫定値 |
| 11 | 発射中の自分のピースが基準へ到達するまで、同じプレイヤーの次の発射を受け付けない | G04未確定。「独断で許可しない」に従い許可しない側 |
