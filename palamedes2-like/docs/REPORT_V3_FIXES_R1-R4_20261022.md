## 2. 修正内容

### R1：ストック列が画面下にはみ出す

**原因**

- 列の上端が論理 y=228 でした。
- PMの再現状態では予約高さが96pxです。開始時予約29＝大5×5＋小4の区画で6区画×16px。
- その下に間隔6pxと、待機24（大4＋小4、5区画＝80px）が続きます。
- このため下端が 228+96+6+80＝**410** となり、画面高360を超えていました。
- 従来の画面内テストは「現在の残量（ブロック＋待機≦29）」を基準にしていました。予約高さ（開始時の量で固定）を基準にしていなかったため、この組合せを検出できていませんでした。

**変更**

- 上端を **y=148** に移しました。Xは維持し、P1 は x=20、P2 は x=604 です。
- 次の項目は変更していません：
  - 予約高さの維持
  - 群の分離
  - 大5／小1
  - 処理中ブロックの点滅枠
  - 相殺（XD顔＋小爆発）とピンチ破棄（フェード）の区別
  - 上詰め（120ms）
- 縮小・省略・切り詰めはしていません。量はすべてアイコンで表示します。
- 配置計算を純粋関数 `stockColumnLayout()` に切り出しました。描画とテストが同じ配置を使うため、テストの対象と実際の描画がずれません。

### R2：攻撃段のせり上がりで上昇音が鳴らない

**原因**

- 演出側（`director.ts`）は、攻撃による `rise` イベントでは上昇音を鳴らさない設計でした。代わりに `attackRow` で鳴らす前提です。
- ところが `attackRow` では `sfx_attack_row` だけを鳴らしており、`se_field_rise` がどこからも鳴っていませんでした。

**変更**

- 鳴らす起点を **`attackRow` の1か所** にまとめました。
- 適用された攻撃1段ごとに、せり上がり開始時（遅延0）に `field_rise` を1回鳴らします。
- `sfx_attack_row` は従来どおり、段の着地時（120ms後）に1段1回です。
- 攻撃による `rise` は引き続き無音なので、二重再生は起きません。自然せり上がりと手動せり上がりの上昇音は、従来どおり `rise` から鳴らします。
- 相殺された分とピンチで破棄された分には `attackRow` が発生しないため、音も鳴りません。
- 400ms周期の自然上昇と役保持の後では、`attackRow` の発生数どおりに鳴ります。

**確認手順と結果**

| 項目 | 方法 | 結果 |
|---|---|---|
| 3段適用 → field_rise 3回・attack_row 3回、遅延 0／120ms | 単体 `fixes_v3r.test.ts` | 合格 |
| 破棄を含む状況（適用2段）→ 2回ずつ。破棄分は無音 | 単体 | 合格 |
| 役保持後に適用 → 回数＝attackRow 数（重複なし） | 単体 | 合格 |
| 手動せり上がり → 上昇音1回 | 単体 | 合格 |
| 実ブラウザで攻撃段の着地時、field_rise の再生数＝適用段数 | e2e（Chromium、模擬入力） | 合格 |

### R3：キャラクター選択の決定ボイスが途中で止まる

**原因**

1. 1P の決定ボイスは `main`、2P の決定ボイスは `announce` チャンネルで再生していました。
2. 両者決定から固定900ms後に `startGame()` が呼ばれ、その中の `stopEffects()` が全チャンネルを停止していました。コタロー（1.940s）は約0.96s、アカネ（1.008s）は約0.90sで切れていました。
3. READY も `announce` を使うため、2P の決定ボイスと取り合いになる構造でした。

**変更**

- 決定ボイス専用のチャンネル `select` を設けました。同じチャンネル内でも互いに止めません。
- 固定900ms待機を削除しました。両者が決定したフレームで、ただちに試合を開始します。
  - 試合開始は声を待ちません。
  - そのフレームの残りの入力は破棄し、試合へは素通りさせません。
- 試合開始時の停止は `stopEffects(['select'])` とし、決定ボイスだけを残します。他のボイス・効果音は従来どおり停止するので、一律の持ち越しはしていません。
- 戻る（自分の決定を取り消す）操作では、その人の決定ボイスを停止します（`stopVoice('select', …)`）。
- 再戦・メニュー復帰・リザルトからの開始では `stopEffects()`（保持なし）を使うため、決定ボイスも止まります。

**確認手順と結果**

| 項目 | 方法 | 結果 |
|---|---|---|
| 3キャラそれぞれ、決定1回につき1回再生 | e2e（ずん子・コタロー：選択画面の検査で決定回数と再生回数が一致、アカネ：下段の同時確定検査） | 合格 |
| 標準設定（1P コタロー・2P アカネ）で同一フレームに確定（KeyF＋Comma）→ 両ボイスとも停止記録なし（`stoppedAt=null`）。コタロー1.94s・アカネ1.008s。READY も再生 | e2e（Chromium、模擬入力、音声ノードの記録） | 合格 |
| 両者決定から150ms後の時点で GameScene、固定待機なし | e2e | 合格 |
| メニュー復帰で声を持ち越さない | e2e | 合格 |
| `select` は試合開始で残り、保持指定なしでは停止。`stopVoice` で個別停止 | 単体（AudioBus） | 合格 |
| 取消・再戦で残響が残らない | 単体とコード確認 | 合格。ただし、ブラウザ上で取消直後に該当ノードが止まることの個別検査はしていません |

「終端まで再生」は、音声ノードが途中で停止されなかったという記録にもとづく判定です。**聴感では確認していません。**

## 9. R5：相殺の消失演出と数量・表示の整合

### 9.1 原因

- 相殺の残像は、描画のたびに「その時点の待機群の末尾の下」へ置き直していました（旧 `stockColumnLayout`）。
- このため、爆発中に追加受信があると、爆発が待機群の増えた分だけ下へ押し出されていました。
  - 例：予約29・現残1・待機28 → 12相殺 → 6受信。旧実装では爆発の下端が 250＋80＋40＝370 となり、画面外になります。
- 残像は「プレイヤー・種類・量・開始tick」だけを持ち、所属する群・位置を持っていませんでした。
  - そのため、ブロック開始で待機群が現ブロックへ切り替わっても、残像は新しい待機群の下に残り続けていました。
- 数量そのもの（相殺の即時減算、上限29、相殺対象）は core 側で正しく処理されていました。不整合は表示側だけです。

### 9.2 変更内容

**データ構造（表示専用の消失対象）**

消失演出1件ごとに次を保持します：

- 所属プレイヤー
- 種類（相殺／ピンチ破棄）
- 量
- 開始tick
- 所属する群（相殺＝待機群、破棄＝現ブロック）
- 群の上端からの相対位置

有効なストックの数量は、従来どおり core の状態（nextPending・現ブロック残量）だけから描きます。消失対象は別の一覧で持ち、同じ配列の存在判定では扱っていません。消失対象は上限29の計算・相殺・消化・次ブロックへの取込みのいずれにも関与しません（表示側だけの一覧で、core から参照されません）。

**位置の確定**

- 相殺の位置は、相殺の時点で「相殺後に残った待機群の下」に確定します。
- 複数tickを1描画でまとめて取り込む場合も、その時点の数量を使います。各イベントの時点の数量をイベントに持たせました（後述）。
- 後の受信・相殺で、待機群の末尾へ配置し直すことはしません。
- 群そのものが移動する場合（ブロック終了後の上詰め120ms）は、相対位置のまま群と一緒に動きます。

**独立した開始・終了**

- 相殺ごとに開始tickを持ち、長さは 4コマ×40ms＝160ms です。終了時刻は「開始＋160ms」です。
- 新しい相殺で古い演出を再開始・延長しません。
- 同じ座標の相殺も別の件として保持します（上書きしません）。

**描画順**

| 層 | 内容 |
|---|---|
| 1（奥） | 通常ストック |
| 2 | 処理中ブロックの囲い |
| 3 | 消失演出（XD顔・破棄フェード・小爆発）。同じ層の中は発生順で、新しいものほど前面 |
| 4（手前） | 待機ライン数の数字 |

**待機ライン数の数字**

- 表示する値は nextPending です（消失対象を含めません）。受信・相殺で即時に更新します。
- 位置は待機群の上端の高さで、列の外側です（1P は列の左、2P は列の右）。
- 待機0で相殺演出もないときは表示しません。
- 文字は既存の採用フォント（`drawText`、10px・太字・半透明の帯）です。

**core のイベントへの追加（表示用の数量のみ）**

- `attackCancel.pending`：相殺後の nextPending
- `attackDiscard.block`：破棄後の現ブロック残量
- `blockEnd.pending`：ブロック終了時の nextPending

これらはゲーム処理（数量・時刻・判定）を変えません。複数tickをまとめて取り込む描画でも、イベントの時点の数量で位置を決めるために追加しました。

### 9.3 表示処理の判断と演出打切り条件（コード：`src/view/gameView.ts` の `StockAfterimage` の注記と `onEvent`）

優先順位は指示どおり「状態遷移 ＞ ブロック開始時の表示切替 ＞ 消失演出の継続」です。

| 条件 | 打ち切る範囲 | 理由 |
|---|---|---|
| ラウンド終了（`roundEnd`）、ラウンド差し替え（新ラウンド・新試合・メニュー復帰で表示を作り直す `reset`） | 全プレイヤーの全件 | 状態遷移が最優先 |
| そのプレイヤーのブロック開始（`blockStart`） | そのプレイヤーの全件（相殺の小爆発・XD顔、破棄の残像） | 待機群が現ブロックへ切り替わる。有効な待機だけで現ブロックの色・囲いを始める。数量は減らし直さない |
| ブロック終了時（`blockEnd`）に待機群が残っている | そのプレイヤーのピンチ破棄の残像 | 上詰めしてくる待機群と元ブロック位置の残像が重なり、新しい表示を妨げるため |

- 打ち切った演出は一覧から削除するため、後の描画で復活しません。
- 他のプレイヤーの演出は消しません（所属プレイヤーで識別）。
- 論理イベント順に処理します。同じtickで相殺→ブロック開始の順なら、その相殺の演出は残りません（core の処理順は「役の処理（相殺）→ブロック開始」）。

**一時的な重なりについての判断**

相殺の直後に受信が来ると、待機群が伸びて、確定済みの消失演出の位置と重なります。指示に従い、次のように扱いました。

- 位置を動かさない（押し出さない）
- 新規受信を待たせない、数量を破棄しない
- 消失演出（XD顔＋小爆発）を通常ストックより前面に描く

この重なりの間は、通常アイコンの一部がXD顔に隠れます。誤認を避けるため、待機ライン数の数字（消失対象を含めない）で有効な量を示しています。重なりは最長160msです。

代わりに「重なる通常アイコンを消失演出の下へずらす」方式も検討しましたが、採用しませんでした。有効ストックの配置が一時的に変わり、R1 の画面内保証（予約高さ基準）を崩すためです。

## 13. 仕様から変更・補完した項目（R5・R6）
