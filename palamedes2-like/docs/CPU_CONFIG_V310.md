# CPU 設定と判断のタイミング（v3.1.0）

設定ファイル：`src/data/cpu_config_v310.json`（企画側が数値で調整）。判断処理：`src/input/cpu.ts`、取得経路の探索：`src/input/cpuPlan.ts`。

- 確率は 0〜100（%）、時間は ms。ゲーム時間（60tick/秒）へ四捨五入で換算します。
- 列の順序はすべて「コタロー／アカネ／ずん子」。表記「確率/停止時間」。
- 乱数は CPU ごとの seed 付き乱数（試合の乱数とは別系列）。抽選は判断機会ごとに1回で、0%・100% でも乱数を1つ消費します（設定値を変えても以後の乱数列の位置がずれないため）。
- 抽選の記録は `CpuController.log`（tick・種類・確率・結果）。

## 2. 判断と抽選のタイミング

行動の順序：実行可能性確認 → 成立役の宣言／追加取得の判断 → 目的地の選択 → 移動・打ち上げ → 結果を受けて再判断。

| 抽選 | いつ | 回数 |
|---|---|---|
| 実行可能性 | 毎tick。既存の入力可否（発射・上詰め・入替・不成立の硬直、役処理中、移動中、停止中）に従い、操作できなければ何もしない | 抽選なし |
| 宣言・6ピース役挑戦・4ピース役の宣言率 | 手元（役ストック）または通常／ピンチが変わったとき | 状態ごとに1回。挑戦中は経路が有効な間は再抽選しない。経路が無くなった（場・盤面・残り猶予の変化）ときだけ判断し直す |
| 目的地なしの停止 | 新たに目的地を探す機会 | 1回。停止後は再抽選せず目的地を判断。失念後の再判断・取得不能での再判断には重ねない |
| 手動上昇 | 目的地を探す機会で、残り段数0〜2、手動上昇が可能なとき。宣言と、選んだ6ピース役の挑戦を優先 | 見送ったら、盤面・手元が変わるまで再抽選しない |
| 最適候補 | 目的地を決めるとき（候補が1つなら抽選なし） | 1回。外れは取得可能な候補から seed 付きでランダム |
| 失念 | 移動計画ごとに1回。移動開始後の最初の判断時点で適用（完了済みの移動には適用しない） | 1回。失念後は再判断するが、同じ移動機会では再失念しない |

- 「最適」：現在の目標（4ピース役＝役を作る／6ピース役／ピンチ中は最短で成立可能な役）に対し、見えている盤面だけで最短の取得経路（移動＋打ち上げ＋上詰め硬直の所要時間）を持つ候補。同評価は seed 付き抽選。未来のランダムピースは使わない。
- 4ピース役成立で宣言を見送った場合は「取得後も役が成立し、翻数が高い（同点は近い）」候補。
- 探索の深さは目標までの残り取得数（6ピース役：6−手元、役：4−手元。手元4以上の役なし・手元6は最大2）。
- ピンチ：取得経路の所要時間＋宣言から実際の解除（先頭ラインの消去＝役の導入700ms＋1tick）＋判断余裕 ＜ 有効な残り猶予 の経路だけを採用。取得だけで残り猶予を超える候補は除外。6ピース役が間に合わず今の成立役で助かる場合は宣言へ切り替え（ピンチ中の4ピース役は宣言100%）。
- 候補がない：既存の合法な打開（2段目が当たる列のB入替 → 3段以上の列のB入替 → 手動上昇）。どれもできなければ盤面の変化を待つ（無限停止しない）。
- MODE2：役・宣言・手動上昇・攻撃の判断はしない。最適＝①移動と打ち上げの所要時間が短い ②取得後にも出せる候補が多い ③同評価は seed 付き抽選。停止・失念は MODE1 通常時の値。場の変化で目的地が出せなくなったら失念とは別に再判断。
- 盤面を直接書き換えず、既存の操作入力（Command）だけを出す。移動・打ち上げ速度は既存のまま。意図的な打ち上げミスは使わない。
