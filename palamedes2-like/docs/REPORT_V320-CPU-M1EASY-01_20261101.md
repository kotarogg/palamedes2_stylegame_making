### 1.3 MODE1 の初級だけに適用される根拠

- 有効設定は、`game.mode === 'mode1'` のとき（見積りは MODE1 専用）にだけ `mode1Timing` を参照します。

- MODE2 の判断（`thinkMode2`）が使う `decisionStop` は、`game.mode` が `mode2` のとき共有設定を返します。
- 表の選択に乱数は使っていません。また、乱数を引く箇所（必須待ちの選択、停止の抽選、停止時間の選択）の順番と回数は変えていません。

  - CPU観戦の初期設定は MODE1 の初級同士です。
- 放置デモの対戦は中級を使うため、影響はありません。

## 3. 指定値の確認（提出条件3）

`tests/cpu_mode1_easy.test.ts` で確認しました。

- **実際の待ち処理**
  - MODE1 初級の `decisionStop` に、短・標準・長の組み合わせ9通り×通常／ピンチを与えました。
  - 必須待ちの終了 tick＝開始＋`game.ticks(必須待ち)`、停止の終了 tick＝それに＋`game.ticks(停止)`（既存の tick 換算）で、すべて指定値どおりでした。
  - 例：540ms は 32tick、1350ms は 81tick。
- **実プレイ**
  - 既定の設定で、MODE1 のゲームを12 seed×3キャラ、各2400tick 進めました。
  - 記録された必須判断待ちと、当たった判断停止は、すべて指定値の候補でした。
  - tick の合計は、各 ms の換算の和と一致しました。
  - 候補の選択比は、おおむね 25／50／25 でした（短 17〜33％、標準 40〜60％の範囲）。
- **待ちと停止の順序、ピンチ移行時の半減**（既存の処理のまま）
  - 必須待ち 32tick → 判断停止 81tick の順に進みます。
  - 10tick 後にピンチへ移ると、残り 22→11tick、81→41tick に、それぞれ1回だけ半分になります。
  - 最初の操作は開始から 62tick 後でした。
- **所要時間見積り**
  - 3キャラ×通常／ピンチで、`expectedMandatoryMs`＝指定値の重み付き平均、`expectedStopMs`＝停止確率×指定値の重み付き平均でした。
  - 例：あかね・ピンチの停止は 0.5×（473×0.25＋675×0.5＋878×0.25）＝337.625ms、必須待ちは 270.25ms。
- **MODE2 の初級**は従来どおり 400＋1000ms、**MODE1 の中級**は変更前と同じ終了 tick でした。
