# 第3版 残課題（v3.0.0-rc1、2026-10-21）

## A. 判断をお願いしたい事項（ゲーム結果に影響）

1. **CPU同士の計測で、全80ラウンドが33〜57秒で決着し、決着原因はすべて攻撃ピンチ（2000ms猶予切れ）**（`docs/CPU_BALANCE_V3.md`）。
   - 準備書5.2の旧ルールでは全80ラウンドが10分上限で未決着だった。
   - 主な要因（推測を含む）：役連鎖の受付12秒に対し CPU の宣言間隔が約5〜6秒のため、連鎖が試合を通じて途切れず（連鎖加算が攻撃力の約7割）、攻撃で7段に達すると2秒の猶予内に CPU が6段以下へ戻せない。
   - 攻撃力・相殺効率・猶予時間は指示どおり変更していない。改善案（採否は企画判断）：ピンチ猶予の延長、連鎖加算の上限や受付時間の見直し、CPU のピンチ時の優先行動。人間のプレイとは同一視できないため、人間の試遊での確認を推奨。

## C. 補完した仕様（指示に明記がなく、ゲーム結果に影響しない）

1. 攻撃ピンチ猶予中も既存の危険警告音を鳴らす（破棄そのものは無音）。
2. CPU対戦の最終結果が引分けの場合、負けと同じ選択肢（同じ相手に再挑戦／メニュー）。
3. 相殺の残像（XD顔＋小爆発）は待機群の現在の末尾の下に、ピンチ破棄の残像は処理中ブロックの残りの下に表示。
4. 受攻撃ストックの列位置（1P x=20、2P x=604、上端 y=228）は画面見本の位置を基準に、合計29で画面内に収まる範囲で決定。
5. キャラクター選択で両者決定から試合開始まで900ms（決定ボイスを切らないため）。
6. 表示倍率の固定倍率は ×1〜×6。オプション「表示」の説明に devicePixelRatio を表示。
7. center_frame（読込一覧に含まれる）は画面見本どおり対戦画面に描画していない。

## D. 既知の制約・注意

1. DPR が整数でない環境では CSS 寸法が小数（例 DPR1.5・2倍＝853.33px）になる。キャンバス要素の配置位置がブラウザ側で実画素境界からずれると、まれにドットの不均等が出る可能性がある（実機未確認）。
2. 開発版の計測記録は MODE1 対戦のみ（シングル・MODE2 は対象外）。
3. 単一ZIPは作成できていない（`docs/DELIVERY_V3_20261021.md`）。
