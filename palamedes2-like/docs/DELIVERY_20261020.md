## 2. 保存方法と再取得検証

| 対象 | 保存方法 | 再取得による確認 |
|---|---|---|
| テキスト（HTML・JS・md・bat 等） | コネクタで内容を送信 | 保存後に再取得し、SHA-256 が手元と一致 |
| PNG・JSON・効果音・ボイス | Drive 内で原本をサーバー側コピー | プレイ版：99ファイルを再取得し、手元の組立て版とバイト一致（`diff -r`） |
| BGM 3本（12,053,804／16,588,844／16,750,124 bytes） | Drive 内で原本をサーバー側コピー | 10MB超のためコネクタで取得不可。Drive 上のファイルサイズが原本と一致 |
| ソース | 同上 | テキスト69件の SHA-256、バイナリ93件のサイズが一致。各フォルダの重複・余分なファイルなし |

再取得したプレイ版での検査結果：

- `node scripts/check-release.mjs <再取得フォルダ> --allow-missing-bgm`：4/4 PASS
  - 素材92件（BGMを除く）のサイズ・SHA-256・WAVヘッダ
  - JS参照の一致、旧ハッシュJSの残存なし
  - 起動ファイルの同梱、bat の ASCII・CRLF
- `E2E_ROOT=<再取得フォルダ> node scripts/e2e.mjs --fallback`：46/46 PASS
  - 再取得フォルダを単独配信して全モードを起動し、R1〜R3 の回帰を確認

BGM を含む「納品検査」（`npm run e2e`、`check-release.mjs` の既定）は、作業環境に BGM を取得できないため、BGM の項目だけ不合格になります。
企画側の中間評価では、正式BGM入りのコピーで BGM 3曲の実ノード作成・ループを確認済みです。

## 3. ZIP について

単一ZIPは保存していません。

- 理由：Drive コネクタはファイル内容をツール呼出しの本文として送る方式です。BGM を含む約53MB の ZIP は送れません。BGM を除いた約8MB でも、正確な転送は実用上できません。
- 代わりの取得方法：Drive のプレイ版フォルダを右クリック →「ダウンロード」。Drive が ZIP にまとめるので、展開して `start-windows.bat` を実行してください。
