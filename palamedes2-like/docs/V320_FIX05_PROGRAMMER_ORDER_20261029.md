## 2. 打上連鎖：時間制限を撤廃
成功取得の間が何秒空いても、時間経過だけでは打上連鎖を切りません。
連鎖数とヒビ状態を正規の状態として保持し、「残り猶予>0」を連鎖の有効条件に使わないでください。
設定で無期限を表す場合はnull等の明示的な型を使い、0を無効／無期限の両義にしたり、Infinityを保存JSONへ渡したりしないでください。具体的な内部表現は任せますが、全参照経路を整合させてください。

- 初回成功：連鎖数1。次の成功で+1。
- 最初の打上失敗：連鎖切り予約に入り、既存の数字へのヒビと揺れを開始。
- 予約中に成功：成功数は増えるが、予約とヒビは解除しない。
- 予約中に再度失敗：成功を間に挟んでいても連鎖を終了し、数・予約・ヒビをリセット。
- 最初の失敗時に有効な連鎖がない場合の扱いは現行を維持。空の連鎖へヒビを新規表示しない。
- 失敗は各ピースの失敗判定イベントにつき1回だけ数える。接触・反発・帰還で同じ失敗を重複計上しない。
- 新ラウンド・再戦・新試合では通常どおり初期化。メニュー・破棄から演出が復活しない。
- ステージ移行では既存の成功数・倍率引継ぎを維持。旧「猶予3000msを復帰」の処理は無期限化に整合させ、別の理由によるヒビ解除を追加しない。
- 攻撃倍率・得点倍率の計算、有効表示、セーブ項目、教材、設定JSON、計測、試験から、旧3秒切断に依存する経路を洗い出して更新。

## 4. MODE1 CPUの調整
現行 candidatesOf は必ず成功する最上段だけを列挙する。「最適手選択に外れた」場合も成功候補から選ぶ。
planValid も打上成功条件を常時再確認するため、入口だけに認識誤りを追加しても、発射前に取り消されて効果が消える。
従って単純な bestPick の引下げでは不十分。
CPUはゲームが公開する同じ盤面・場・手役だけを読む。未来の乱数や非公開情報は読まない。
連鎖カウンターを直接書き換える、勝率を見て故意に負ける、一定連鎖数で強制失敗させる処理は行わない。

### 4.2 認識誤りの抽選と受け渡し
1. 新しい取得目標を決める判断につき1回、実在して打上操作できる各列最上段と場を読み取る。
2. 誤認／見落とし／正しく認識の3択を、それぞれ上表の確率・残余確率で1回抽選する。列ごとに独立抽選しない。
3. 誤認なら、実際には合わない操作可能ピースから1つ選び、認識上の成功候補へ追加する。
4. 見落としなら、実際に合う候補から1つ選び、認識上の候補から除外する。
5. 当選した種類に該当する列がなければ変化なし。引き直し・確率の再配分はしない。
6. 見落としで候補0になったら、その判断では認識した盤面に基づき通常の打開・再判断へ進む。裏で完全情報の成功候補へ差し戻さない。
7. 最適手評価・ランダム選択・短経路探索の入口も同じ認識結果を使う。誤認候補が実際に失敗するという理由で評価前に除外しない。
8. 選択後の計画は同じ判断の抽選結果を保持。1列移動ごと・描画フレームごとに誤認を再抽選しない。
9. 発射は人間と同じコマンドから行う。成否、飛行、帰還、連鎖切断はゲーム本体が判定する。誤認したら必ずその列を選ぶわけではない。
10. 発射可能な物理状態（空列・帰還予約・入力硬直など）は厳守する。発射前の完全な成否再判定で誤認だけを消してはならない。
11. 場や対象ピースのIDが変わった場合は古い計画を破棄し、新しい判断へ進む。同一判断を毎フレーム無限に引き直さない。
12. ピンチへの移行では残り必須待ち・既存の判断待ちを各1回だけ半分にする。所要時間の見積りも新設定を参照する。
13. 役宣言か追加取得かの判断にも必須待ちは適用するが、認識誤りは取得候補を読むときだけ。宣言そのものの成立条件を偽装しない。
14. 探索深さの上限は通常の役作りと6ピース挑戦判定に適用。7個目の改善は既存の1取得比較と確率判断を維持する。候補0時の打開処理も認識と矛盾させない。
15. これらの設定をCPU調整用ファイルへ分離し、MODE・難易度・キャラ・状況別に受け入れる。


### 4.3 実装時の補足
新しい認識誤り・探索制限・中上級必須待ちはMODE1のみです。MODE2のCPU思考設定は維持します。
初級の認識・探索・待ちの設定はFIX-04-R1を維持します。無期限化など共通ルールの影響は別に計測します。
「誤認率＝実際の打上失敗率」ではありません。誤認候補が選ばれなければ失敗は起きません。抽選率を失敗率として報告しないでください。
最適候補評価の内部で誤認候補を真の成否で消す、候補0時に完全情報へ無言で戻す、planValidで誤認を必ず救済する、という抜け道を残さないでください。
逆に、誤認に当選しただけで発射先を強制固定したり、失敗結果を注入したりしないでください。
探索・評価に認識結果を通す方法は設計判断を任せます。処理と表示の整合、停止中の再判断の無限ループ防止、決定性を優先し、採用した方式を報告してください。
初級の旧操作列との比較は、新旧で共通ルール・seed・待ち設定を揃えて行ってください。乱数を使わない0%設定で余分な乱数を消費して、初級やMODE2の操作列を変えないようにしてください。
入力にない操作やゲーム状態の直接書換えで、CPUを有利・不利にしないでください。

## 6. 役名の横スライドと表示時間
### 6.1 表示仕様
表示位置と原寸画像を維持します。縦2段、別の表示枠、小型ロゴの制作は不要です。
- 移動量：16論理px。
- イン120ms：外側16pxから基準位置へ。減速して停止。透明度0→1。
- アウト120ms：基準位置から内側16pxへ。加速して消失。透明度1→0。
- 1Pは左→右、2Pは右→左。
- 補間位置は整数pxへ丸める。画像の拡大縮小・回転・ぼかしは追加しない。
- インはease-out quadratic、アウトはease-in quadratic、透明度は各区間で線形とする。
- A/B/C色替えは各ロゴの表示開始を起点に既存周期を維持。
- 時間は固定。ボイス尺、音量、デコード状態、再生可否で変えない。
- 既存固定設定の先頭600+追加待機150＝750ms、後続600msを基準にし、出入り120msはこの表示時間内に含める。
- 同じ表示領域に最大2枚を描画できるようにする。先行役のアウトと後続役のインを同じ120msに重ねる。

### 6.2 具体的な時系列（宣言からの経過）
単役（専用複合ロゴを含む）：
- 0〜120ms：イン。
- 120〜630ms：定位置表示。
- 630〜750ms：アウト。
- 750ms以降：非表示。

2役：
| 時刻 | 先頭役 | 後続役 |
|---|---|---|
| 0〜120ms | イン | 非表示 |
| 120〜630ms | 静止 | 非表示 |
| 630〜750ms | アウト | イン |
| 750〜1110ms | 非表示 | 静止 |
| 1110〜1230ms | 非表示 | アウト |
| 1230ms以降 | 非表示 | 非表示 |

先頭750ms、後続600ms、重複120ms、全体1230msです。
重複は切替中のみです。上下や左右に別の定位置を作らないでください。後続を前面に描き、旧役・新役それぞれの透明度を適用します。
各時刻は宣言時刻から一度だけtick換算し、境界を共有してください。60Hzの量子化誤差は1tick以内で許容します。区間ごとの丸めを加算して時間を延ばさないでください。
新しい宣言では旧表示を打ち切り、新宣言の先頭から開始。古い後続をキューに残したり、後から再開したりしないでください。
勝敗確定・ラウンド切替・メニュー復帰・破棄でも表示を終了します。
役処理導入1200msは維持し、表示全体1230msのために硬直を延長しません。

### 6.3 役とボイスの一致
- 表示順は既存の役データに従います。数字役→属性役。専用のストレートフラッシュ系ロゴへ統合される場合は1枚です。
- 宣言時に採択役、表示リスト、先頭役ID、対応ボイスIDを1つの宣言単位で確定し、表示開始と代表ボイス要求を同時に行います。
- 複数役でも代表ボイス1本。後続役のボイスは追加しません。
- 既存の代替攻撃ボイス抽選（20%、前回が代替なら次回は役名）を維持し、役名と代替ボイスを同時再生しません。
- 表示の切替・終了だけを理由にボイスを止めません。表示をボイス尺まで延長することもしません。
- 新宣言・勝敗等で別のボイスが要求された場合は既存の音声優先度に従います。本件で音声優先度全体を独断変更しません。
- 発注者の実機報告は「読み上げと役文字が合わない」です。優先度を直したことにするだけで閉じず、素材番号の対応、実際の先頭表示、プレイヤー側、実再生要求を調査してください。
- コード上の先頭ID一致だけで聴感一致を断定しないでください。ロゴR番号・正式役名・ボイスファイル名・再生開始・実描画開始と終了をログで対応させてください。
- 左右同時宣言、数字役＋属性役、専用複合役、代替ボイスあり／なし、ボイス無効／有効、長い音声、新宣言と勝敗の割込みを検証します。
- 不一致の原因と再現条件を報告。不一致を再現できなければ、再現できたと偽らず未再現と記載し、対応ログを納品してください。
- 長いコタロー「スーパーストレートフラッシュ」3.48秒は単役ロゴです。2枚切替の基準に用いません。

## 8. 検証と計測
まず必要な単体・回帰検査、型検査、ビルドを行い、その後に描画検査とCPU計測を行ってください。

必須の機能確認：
1. 打上連鎖：長い待機で切れない、失敗→成功→失敗で切れる、同じ失敗を重複計上しない、倍率計算と表示が一致、新ラウンドへ残留しない。
2. 役連鎖：実減算10秒の境界、役処理中停止、ステージ復帰、ゲージ一致。
3. CPU：認識の抽選対象・当選・変更・選択・発射・実成否を区別。誤認の前面救済がない。0%で無駄な乱数消費がない。設定とseedが同じなら再現。初級・MODE2へ新設定が混入しない。
4. 役名：0/120/630/750/1110/1230ms付近を実素材で描画し、原寸・定位置・16px移動・透明度・2枚重複・後続の静止時間・終了を確認。単役は750msで終了。
5. ボイス：表示順・代表役・対応ファイルを確認。デコードの有無や実尺で表示の時系列が変わらない。
6. ピンチ：盤面に大型数字と残秒が残らず、文字は指定領域内。左右同時・最大ストック・役名演出中でも重要表示を隠さない。
7. 教材・デモの完走。40項目全体を無条件に作り直すのではなく、影響箇所と必要な回帰を確認。
8. 正式BGM・フォントが手元にない場合、フォールバック検査と未確認を明記。欠落許容を正式素材合格と呼ばない。

CPU計測：
- 小規模比較：MODE1中級、コタロー対アカネ／アカネ対ずん子／ずん子対コタロー、seed1〜5。
- 新ルール＋旧CPU設定、同じ新ルール＋FIX-05 CPU設定を各15ラウンド、計30。ルール変更とCPU変更の影響を分ける。
- 機能に異常がなければ、FIX-05設定で3難易度×上記3組×seed1〜10、90ラウンド。小規模比較と同一条件の15件は再利用し、重複実行しない。
- 上限は1ラウンド180秒。上限到達は未決着として必ず件数を報告。平均・中央値等から除外した場合は「決着例のみ」と明記。
- 自然上昇はそれぞれの難易度の現行設定。キャラ補正や勝敗補正は入れない。
- 指標：決着時間の平均・中央値・p10/p90、未決着数、実打上成功／失敗、最大打上連鎖・切断原因、最大役連鎖・切れた回数、宣言間の役猶予実減算、攻撃生成・相殺・実送信、ピンチ到達・解除。
- 初級は旧候補選択と一致する設定確認を優先し、体感難易度が維持されたとCPU同士の数値だけで断定しない。
- 打上連鎖60超を一律不合格にしない。時間制限がなくなるため、実際の成功・失敗と連鎖の関係を見る。
- 各試合で必ず役連鎖を切る目標は置かない。実際に10秒以内で成立宣言できれば継続が正しい。
- 既存540ラウンドの無条件再計測や、不要な試験の反復はしない。
- 異常・極端な弱体化・長期戦があれば、値を無断変更せず、seed・再現条件・指標・少数の改善案を報告。
