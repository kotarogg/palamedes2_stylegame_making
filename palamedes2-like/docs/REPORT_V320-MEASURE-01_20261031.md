### 0.4 役連鎖継続率：定義案（提出時の内容。**PM確認後の確定定義と実装は 0.6**）

**現行の実装（変更なし）**

- 分母：同じラウンド内の全宣言（成立した宣言）
- 分子：次の宣言の連鎖数が＋1 だった宣言
- 例：宣言列 `[1,2,3]` は 2／3＝66.7%
- 問題点：最後の宣言は「時間切れで途切れた（失敗）」のか、「ラウンド終了や計測の停止で結果が分からない（未確定）」のかを区別できず、どちらも失敗として数えています。

**ゲームの仕様**（`src/core/game.ts`。記録で観測できる形もあわせて示します）

- 成立した宣言のたびに、役連鎖の受付時間が 10000ms（600tick）に戻ります。
- 受付時間は、自分の役処理の間（`p.role`）と、SINGLE のノルマ達成後の待ちの間は減りません。
- 受付中に次の宣言が成立すると、連鎖数は＋1 になります。受付時間が 0 になった後の成立は、連鎖数 1 から数え直しになります。
- 不成立の宣言は、受付時間にも連鎖数にも影響しません。
- SINGLE のステージ移行では、連鎖数を引き継ぎ、受付時間を 10000ms に戻します（ラウンドID は変わります）。
- 記録の状態差分 `st.chain` は、受付中は連鎖数、受付が切れた tick に 0 になります。そのため、**時間切れが起きた tick を記録から特定できます**。

**定義案**

- 単位：人間のプレイヤーが成立させた宣言1件ごとに「継続機会」が1回あるとみなします。
- 判定（宣言 D、連鎖数 n）

| 判定 | 条件 |
|---|---|
| **成功** | 同じプレイヤーの次の成立宣言が連鎖数 n＋1。SINGLE のステージ移行をまたいだ場合も含めます |
| **失敗確定（時間切れ）** | 次の成立より前に `st.chain` が 0 になった。補助として、次の成立の連鎖数が 1 だった場合（記録から欠けていても失敗と分かる）も含めます |
| **未確定（打ち切り）** | 受付中のまま、次のいずれかになった：(a) ラウンド終了（自分の敗北／相手の敗北／引き分け／SINGLE の終了）、(b) 計測停止のまま記録が終わった、(c) 記録の終端 |

- 指標
  - **役連鎖継続率＝成功÷（成功＋失敗確定）**
  - 未確定は分母に入れず、理由別の件数を必ず併記します。
  - 連鎖数ごとの率（1→2、2→3、…）も出します。
- 計測の停止と再開
  - 再開時には、記録器がラウンド全体（各プレイヤーの `chain` を含む）を記録し直します。
  - 停止中に受付が切れていた（再開時に chain が 0）場合は、**失敗確定**です。ただし起きた時刻が分からないため、時間に関する指標からは外します。
  - 受付が続いていた場合は判定を続けます。
  - 停止中に宣言があった（再開時の連鎖数が n より大きい）場合、D は成功です。停止中の宣言そのものは観測できていないため、数えません。
- 非表示・フォーカスを失っていた時間：受付時間とその時間が重なった機会は、主の率から外し、件数を別に示します。ゲームは止まらないため、プレイヤーが判断できない時間を含むからです。
- 時間に関する補助指標（成功した機会のみ）
  - 役処理の完了（`roleEnd`）から次の成立までの時間
  - 成立した時点での受付の残り時間

**計算例**

| 例 | 宣言の流れ | 成功／失敗確定／未確定 | 定義案の率 | 現行の率 |
|---|---|---|---|---|
| 1 | 1→2→3、その後に受付が切れる | 2／1／0 | 66.7% | 66.7% |
| 2 | 1→2→3、受付中に相手が敗北してラウンド終了 | 2／0／1（相手の敗北） | **100%** | 66.7% |
| 3 | 1→2、受付が切れる。1、受付中に自分が敗北 | 1／1／1（自分の敗北） | 50% | 33.3% |
| 4 | 1 の後に計測を停止。再開時に chain が 0 | 0／1（時刻不明）／0 | 0% | 0% |
| 5 | SINGLE：1→2、ステージ移行、次の面の最初の成立が 3、受付中にゲーム終了 | 2／0／1（SINGLE の終了） | 100% | 33.3%（ラウンドで区切るため、面をまたぐ継続を数えない） |

**PMにご判断いただきたい点**

1. 自分が敗北して受付が打ち切られた場合
   - 案：未確定とし、件数を併記する。
   - 別案：保守的な指標として失敗に数えるもの（例3では 33.3%）を併記する。
2. 非表示の時間と重なった機会を主の率から外すか。
3. SINGLE のステージ移行をまたいだ継続を成功に数えるか（案では数える）。

ご確認いただいてから、集計と報告書の定義を変更します。

### 0.6 役連鎖継続率：確定定義と実装（PM確認 2026-11-01、コミット `680ad92`）

**PMのご判断**

| 質問 | 扱い | 実装上の判定と集計先 |
|---|---|---|
| ① 受付中に自分が敗北 | 未確定として、主の率から除外 | `excluded.undetermined.ownDefeat`。SINGLE のゲームオーバーも同じ扱いです |
| ② 画面非表示と重なった機会 | 主の率から除外 | 機会の開始（成立）から結果が決まるまでの間に、非表示・フォーカス喪失の区間が重なったもの。`excluded.hiddenOverlap` に成功・失敗・未確定の件数を出します |
| ③ SINGLE のステージをまたいだ継続 | 主の率から除外し、ステージ間継続として別集計 | 結果が `stageClear` で、次の面の開始時に連鎖数が引き継がれている機会。`excluded.stageCarry` に成功・失敗・未確定の件数を出します。次の面で新しく成立した宣言は、通常の機会として数えます |

**定義**

- 主の率：`chain.continuationRate`（＝`chain.main.rate`）＝成功÷（成功＋失敗確定）
- 成功：同じプレイヤーの次の成立宣言が、連鎖数 n＋1 になった。
- 失敗確定：次の成立より前に `st.chain` が 0 になった（受付時間切れ）。補助として、次の成立が連鎖数 1 の場合も失敗とします。
- 未確定：結果が出る前に機会が終わったもの。理由ごとに数えます。

| 理由 | 内容 |
|---|---|
| ownDefeat | 受付中に自分が敗北 |
| opponentDefeat | 受付中に相手が敗北 |
| draw | 引き分け |
| singleEnd | SINGLE の最終面クリアなど |
| measureStopped | 計測を停止したまま記録が終わった |
| matchLeft | ゲーム画面を離れた |
| recordEnd | 記録の終端 |
| roundChange | 結果記録のないラウンド切替 |

- 計測の停止・再開
  - 停止中に受付が切れていた場合は、失敗確定です。時刻が分からないため `main.timeUnknownFailures` に数え、時間の指標には使いません。
  - 停止中に宣言が進んでいた場合は、成功です。停止中の宣言は観測していないため数えず、`unobservedDeclaresDuringStop` に件数を残します。
- 出力するその他の項目
  - 連鎖数ごとの率（`byLength`、例：`1→2`）
  - 成功した主の機会について、役処理の完了（`roleEnd`）から次の成立までの時間の分布（`roleEndToNextDeclareMs`）
  - 機会ごとの生データ（`raw`）
- 旧定義（全宣言を分母とし、ラウンドで区切る）は、比較用に `chain.legacy` として残しています。
- 集計結果の形式番号は 1 から 2 に上げました。

## 2. 基準から変更したゲーム設定（全量）

| 項目 | 通常ビルド | 計測用ビルド |
|---|---|---|
| 打上：飛行（操作硬直） | 300ms（変更なし） | A：300ms／**B：200ms（初期選択）** |
| 打上：成功後の列詰め | 120ms（変更なし） | A：120ms／**B：50ms** |
| 成功時の操作ロック合計 | 25tick（約416.7ms） | A：25tick（18＋7）／**B：15tick（12＋3）＝250ms** |
| 失敗時の総帰還時間（飛行＋跳ね返り120＋山なり260＋下降1600） | 2280ms（137tick） | A：2280ms（137tick）／**B：2180ms（131tick）＝100ms 短縮** |
| 跳ね返り・山なり帰還・垂直下降・先行入力（2tick） | 変更なし | 変更なし |
| その他（CPU思考・攻撃力・連鎖ルール・入力の予約範囲など） | 変更なし | 変更なし |

- 適用範囲：計測用ビルドの **MODE1 全種別**（CPU対戦・単独ひたすら・ステージ・2人対戦・CPU観戦）。MODE2 には適用しません。
- プレイヤーと CPU は同じ `Game.config.timing` を使うため**共通に適用**されます（CPU の見積りも同じ値を読む）。単体検査で確認済み。
- 設定は試合の開始時に固定します。計測メニューでの変更は**次に開始する試合から**適用され、試合中やラウンド途中では変わりません。
- 試合の記録（`matchStart`）とラウンドの記録（`roundStart`）に、設定値（ms）と実際の tick 換算（`timingTicks`）を保存します。保存ファイルのヘッダーには A／B 両方の換算表を入れています。

## 4. 計測の開始から保存までの操作

1. メインメニューで「計測（テスト）」を開きます（十字キー／スティックと A、またはキーボード）。
2. 「打上硬直設定」を左右で A／B に切り替えます（初期は B）。右側の値で ms と tick を確認できます。
3. 「入力表示」「時刻表示」を選びます。どちらを非表示にしても記録は続きます。
4. 計測の開始方法は2通りあります。
   - メニューの「計測を開始」を選ぶ。
   - プレイ中に **START（キーボードは Esc）** で確認画面を開き、「続ける／**計測開始**／終了する」から選ぶ。
5. MODE1 の CPU対戦か単独ひたすらを遊びます。ラウンドや試合をまたいでも、同じセッションへ記録が続きます。
6. 計測を停止します。START の確認画面で「計測停止」を選ぶか、メニューの「計測を停止」を選びます。もう一度開始すると、同じセッションへ追記（再開）します。
7. メインメニューの「計測（テスト）」で「記録を保存」を選ぶと、ブラウザのダウンロードとして保存されます。
   - ファイル名は `kotaro_measure_<セッションID>.json` です。
   - 記録中は保存できないため、先に停止してください。
8. 次のセッションを始めるときは「記録を初期化」を選びます。未保存の場合は確認が出ます（「やめる」で記録は残ります）。

### 操作の割当

既存の割当は以下のとおりです。プレイ用のボタンは計測用へ転用していません。

| 操作 | パッドのボタン |
|---|---|
| 左右移動 | 十字キー左右（14・15）／左スティック横 |
| 打上 | A（0） |
| 入替 | B（1） |
| 宣言 | X（2） |
| 手動上昇 | RB（5） |
| 一時停止確認 | START（9） |

- 計測の開始・停止は、既存の一時停止確認（START／Esc）に選択肢を1つ足す形にしました。
- 確認画面を開いている間の入力は従来どおりゲームへ渡しません（`cmdDrop: dialog` として記録）。
- **注意：この確認画面を開いていてもゲームは止まりません（従来仕様）**。計測の開始・停止は、ラウンドの合間か、メニューから行うことを推奨します。

### 記録の保持と離脱時の保護

- メニューへ戻っても、別のモードを遊んでも、記録は保持されます。消えるのは「記録を初期化」またはページを閉じたときです。
- 記録中または未保存のときは、タブを閉じる・再読込するとブラウザの確認（`beforeunload`）が出ます。
- 限界は次のとおりです。
  - ブラウザによっては、そのページで一度も操作していないと確認が出ません。
  - 文言はブラウザ固定です。
  - ブラウザの強制終了・クラッシュ・OS の再起動では記録が失われます。
  - 記録はメモリ上だけにあり、ブラウザの保存領域へは書きません。
- 区切りごとに停止して保存してください。
- 外部への自動送信は一切ありません（保存はローカルへのダウンロードだけです）。

### 上限

- 上限は 30 万件、または 5,000 万文字（メモリ上で約 100MB）です。
- 上限の 80％で画面上部に通知します。上限に達すると計測を自動停止し、記録は保持します。古い記録を黙って捨てることはありません。
- 上限で止まった場合は「保存してから初期化」するまで再開できません。
- 開発環境での測定では、ゲーム時間 20 分で約 3.7 万件・約 6.2MB（上限の約 12％）でした。20 分の約 8 倍の余裕があります。

## 5. 記録形式と集計の定義

### 5.1 ファイル形式（JSON、圧縮なし）

```
{"header":{ format:"kotaro-puzzle-measure", formatVersion:1, workId, app{version,base,baseCommit},
            build{mode,commit,builtAt}, session{id,segments[{start,stop}],records,state,limitStopped},
            settings{selectedProfile, profiles{A,B}, padRecord, limits, snapshotEveryTicks, frameGapMs}, timeBase, env… },
 "records":[ {s,t,f,m,r,k,e,d}, … ]}
```

#### 共通キー

| キー | 内容 |
|---|---|
| `s` | 全体の連番。順序はこれが正 |
| `t` | セッション開始からの ms（`performance.now` 基準。`Date.now` は順序に使わない） |
| `f` | 描画フレーム（パッド取得）の連番 |
| `m` | 試合ID |
| `r` | ラウンドID |
| `k` | ラウンド内のゲーム tick（60tick／秒） |
| `e` | 記録の種類 |
| `d` | 内容 |

ラウンドが変わって `k` が 0 に戻っても、`s` と `t` で全体の順序を保ちます。

#### 記録の種類（`e`）

- 計測の区間
  - `measureStart`：区間番号、選択中の設定、A／B 換算、環境（UA・パッド一覧）、壁時計（参考）
  - `measureStop`：区間番号、理由（user／limit）
- 環境
  - `visibility`：hidden／focused／cause（visibilitychange・blur・focus）
  - `frameGap`：50ms を超えるフレーム間隔（処理遅延）
  - `scene`：画面の切替
  - `matchLeave`：ゲーム画面を離れた
- パッド：既存の取得結果を、記録中だけ変化判定して記録します
  - `padInfo`：id・mapping・ボタン数・軸数
  - `padBtn`：ボタン番号・pressed・value
  - `padAxis`：軸の生値
  - `padDir`：0.5 閾値の方向判定の変化
  - `padGone`、`padConnected`／`padDisconnected`
- キーボード：`keyDown`／`keyUp`（code・repeat・イベント時刻）
- コマンド
  - `cmd`：ID・プレイヤー・操作・反復（`rep`）・入力元（pad／keyboard／cpu）・入力時刻・パッド番号
  - `cmdDrop`：ゲームへ渡さなかったもの。理由は dialog／result／prestart／focusLost
- 入力の追跡 `in`（ゲーム内部の結果）
  - `kind` は次のいずれかです：execute・reject・buffer・consume・discard・drop・lock
  - `id` は `cmd` の ID に対応します
  - 予約の実行は `d.via=buffer` です
  - 理由は次のとおりです。

| 区分 | 理由 |
|---|---|
| 操作ロック | launch・pack・rotate・declareFail・role・defeated |
| 実行できない | edge・emptyColumn・returningColumn・singlePiece・tooFew・riseInProgress・riseLimit |
| 予約 | overwritten・expired・released・simultaneous・repeatIgnored・locked・state |
| 受付外 | notStarted・roundEnded・clearPending |

- 試合・ラウンド
  - `matchStart`：モード・種別・キャラクター・機器・人間のプレイヤー・難易度・先取数・seed・設定と換算。途中から開始した場合は `why=measureStart`
  - `roundStart`：seed、設定の実効値と tick 換算、開始 tick、盤面全体のスナップショット
  - `session`：試合／ラウンド結果の状態（state・wins・round）の変化
- 状態
  - `ev`：ゲームイベントを全件、圧縮表記で記録します。対象は次のとおりです。
    - 移動・発射・到達（成否）・帰還・入替
    - 上昇（自然・手動）
    - 宣言（役・採用ピース・消去数・基本攻撃・連鎖数・打上連鎖加算）、成立（roleAvailable）、役終了
    - ライン消去・攻撃・受信・相殺・ブロック・波・段の適用・破棄
    - ピンチ・危険・連鎖切れ
    - スコア・進行・Lv・全消し・ノルマ・ステージ
    - ラウンド終了（勝者・結果）
  - `st`：変化した項目だけの差分です。プレイヤーごとの項目は次のとおりです。
    - 選択列、ロック理由と終了 tick、移動終了 tick、予約（操作@tick）
    - 手役、成立中の役（ロゴ・消去数・基本攻撃）、役の段階
    - 打上連鎖数、連鎖切れ予約、役連鎖数（＋残り）、危険猶予・ピンチ猶予の有無
    - 受攻撃（ブロック／残り／波／次）、盤面（列ごとのピースと帰還予約位置）、敗北
    - 場のピース、SINGLE のスコア・Lv・進行
  - `snapshot`：600tick（10 秒）ごとの確認用の全体
- 記録しないもの
  - 全フレームの複製（初期全体＋差分＋定期スナップショットで代替）
  - 画面・音声の録画、OS 全体の入力監視

#### パッド記録の間引き

ゲーム側の取得（毎フレーム・値・回数）は変えず、記録だけを間引きます。

- ボタン：pressed の変化は常に記録します。value は 0.05 以上の変化だけ記録します。
- 軸：0.001 に丸め、0.02 以上の変化と 0 への復帰を記録します。方向判定の変化は常に記録します。
- 計測開始時には、押しているボタンと軸の全値を記録し直します。

#### 時刻について

- `t` は「取得したフレームの観測時刻」です（精度は約 1 フレーム）。**物理的な押下時刻ではありません**。
- `Gamepad.timestamp` は実装差があるため、参考の生値（`ts`）として残すだけです。
- 「役が成立していた時刻（roleAvailable）」は記録しますが、プレイヤーが**認識した時刻ではありません**。

### 5.2 集計（`npm run measure:analyze -- <保存ファイル> [出力.json]`）

件数・中央値・平均・最小・最大・10／90％点・度数分布・生の値（`raw`）を出力します。判断の正誤や最善手率の自動採点はしません。

| 指標 | 定義 |
|---|---|
| 新規押下の間隔 | 人間のコマンドのうち反復でないもの。同じ入力元・プレイヤーで連続する2件の入力時刻（`t`）の差。全操作と操作別 |
| 同じ操作の反復間隔 | `rep=1` のコマンドの直前の同じ操作からの間隔（左右の押しっぱなし） |
| 押下時間 | パッドの `padBtn` 押下→離し（ボタン別）、キーの `keyDown`→`keyUp`（repeat 除外）。切断・停止で対応を捨てる |
| 受理・予約・破棄の率と理由別件数 | 人間のコマンド1件ごとに最終結果を決め、操作別にも集計 |
| 操作可能→次の実行 | 人間のロック理由が none かつ移動中でなくなった tick から、次の execute までの tick 差（ms 換算） |
| 状態別の時間 | ロック理由別（launch／pack／rotate／declareFail／role）・移動中・操作可能（operable）の合計 ms。開始前待機は除く |
| 打ち上げ成功率 | `arrive` の success（人間・CPU 別） |
| 連鎖切れ | 予約（reserved）と終了（ended）の回数、終了時の連鎖数の分布 |
| 宣言 | 回数、同じラウンド内の宣言間隔、成立（roleAvailable）から次の宣言までの時間、不成立宣言の数 |
| 役連鎖の継続率 | **訂正（確定定義、`680ad92`）**：成功÷（成功＋失敗確定）。未確定（理由別）・非表示と重なった機会・SINGLE のステージ間継続は除外して別に集計。詳しくは 0.6。旧定義（全宣言を分母）は `chain.legacy` |
| ピンチ回復率 | ピンチ警告の end のうち、同時刻に敗北・相手勝利でないもの／（回復＋敗北） |
| ラウンド・試合 | ラウンドの開始〜終了の時間（tick）、勝者・結果。試合の勝数・終了・所要時間 |

コマンドの最終結果は次の6種です。

- executed：その場で実行
- executedBuffered：予約して後で実行
- rejected（理由）／bufferRejected：実行できなかった
- bufferDiscarded（理由）：予約を破棄
- discarded（repeatIgnored／simultaneous）
- dropped（理由）：ゲームへ渡さなかった

集計時の扱いは次のとおりです。

- 非表示・フォーカス喪失の区間、計測停止〜再開の区間に掛かる間隔は除外し、除外した件数を `excluded` に出力します。プレイヤーの判断時間には混ぜません。
- ゲーム内の時間は tick 換算です。ゲームは非表示中も止まらないため、状態別の時間に非表示の区間も含まれることがあります。必要なら `hiddenIntervals` で切り分けてください。

見本は `docs/measure01/sample_analysis.json`（ブラウザ検査の保存ファイルから作成）です。**訂正**：修正版 `2dc13a9` で取り直した記録（`saved_kotaro_measure_M01-20261101-015655-eb70.json`）から作り直しました（0.3）。

## 7. 発見した不具合と再現（すべて修正済み）

（独立検証で見つかった3件、ビルドの型エラー・Windows の CLI・改行形式への依存は、0.1 に記載しています。）

1. **上限到達時の無限再帰**
   - 再現：上限を小さくした記録器で上限まで記録する。
   - 原因：上限到達時に停止処理が停止の記録を書き、その記録で再び上限判定が走って停止処理を呼び直していた。
   - 修正：上限停止済みなら判定しない。検査を追加。
2. **試合の途中から計測を始めると、試合情報とラウンドの全体が記録されない**
   - 再現：MODE1 の試合中に START→「計測開始」→ラウンドを1つ終える。
   - 修正：計測開始時に、現在の試合情報（`matchStart`）とラウンドの全体（`roundStart`、`why=measureStart`、ID は変えない）を記録する。ゲーム画面を離れたら古い試合情報を捨てる（`matchLeave`）。
3. **パッドの `Gamepad.timestamp` が 0 の環境で押下時間が 0 になる**
   - 修正：押下時間は取得の観測時刻 `t` で算出し、`ts` は timestamp が正の値のときだけ参考に残す。
4. **試合結果の記録が無かった**
   - 修正：試合／ラウンド結果の状態の変化を `session` として記録。
5. **ブラウザ検査の手順誤り（製品の不具合ではない）**
   - 結果表示で A を連打して試合結果メニューを選んでいた。
   - 確認画面で左を押すと、先頭から末尾の「終了する」へ回り込んでいた。
   - 修正：検査手順を直した（待ち時間に上限も設定）。
   - 補足：確認画面の左右は回り込む仕様で、計測用の 3 択でも同じです。

## 8. 実装上の判断

- **観測の方法**
  - 既存の処理をそのまま使い、前後で読むだけです。
    - 入力は、既存の `PadSource` を包み（同じ値を返し、取得回数は同じ）、既存の各 `Controller.poll` の結果を記録します。
    - ゲーム内部は `Game.trace`（既定 null）の呼び出しだけです。
  - 別の取得ループは作っていません。コマンドの順番・処理回数・予約の挙動は変えていません（ON／OFF 一致検査で確認）。
  - 既存の 500 件の `inputLog` には依存しません。従来は黙って return していた入力（ロック中・ラウンド外・ノルマ達成後・実行できない理由）にも記録を追加しました。
- **予約の破棄と元のコマンドの対応付け**
  - 予約の期限切れ・上書き・離しなどは、既存処理がコマンドを持たないまま記録します。
  - 1 プレイヤー 1 枠の予約なので、集計側で「その枠の予約を作ったコマンド」へ対応付けています。
  - 左右同時押しの中立は、同じフレームの新規の左右コマンドへ対応付けています。
- **計測の開始・停止の操作**
  - プレイ用のボタンを転用しないため、既存の一時停止確認（START／Esc）へ選択肢を追加しました。
  - 既存の割当と競合するボタンはありません。
- **記録量**
  - 毎tick変わる残り時間（役連鎖の残りなど）は差分に入れず、値が変化した時に添えます。
  - 盤面は文字列表現です。
  - 600tick ごとの確認用スナップショットで、差分の欠落を検出できます。
- **保存**
  - 巨大な1文字列を作らず、行の配列から Blob を作ります。
  - 圧縮はしていません（JSON のまま。展開手順は不要です）。
- **MODE2**
  - 依頼の必須範囲外のため、コマンド（`cmd`）は記録しますが、入力の追跡（`in`）・状態の差分・打上硬直の設定は対象外です。

## 9. 未確認事項・制約・PM判断事項

### 未確認事項

- **実機のゲームパッド**（接続・切断・mapping・アナログ値・取得周期）は未確認です。検査はすべて模擬パッドです。
- 実際のブラウザ（画面あり・GPU）での描画を含む負荷は未測定です。
- 長時間（20 分）の連続計測は、ロジックの測定のみで行っています。
- `beforeunload` の確認が出るかは、ブラウザと操作履歴に依存します。

### 制約

- 確認画面を開いてもゲームは止まりません（従来仕様）。プレイ中に計測を開始・停止すると、その間の操作はできません。
- 記録はメモリ上だけです。クラッシュ時には保存されません。
- 押下時刻は取得フレームの観測時刻です（約 1 フレームの精度）。物理的な押下時刻ではありません。
- 「プレイヤーが役を認識した時刻」は記録できません。成立した時刻だけを記録します。

3. 記録上限（30 万件／5,000 万文字）の妥当性。
4. 次の段階で、MODE2 の入力の追跡と状態の記録を加えるか。
