## 2. 打上連鎖：時間制限の撤廃（第2章）

- 設定 `streakWindowMs` は `number | null` 型です。既定は **null（時間制限なし）** です
  - 0 や Infinity を「無期限」の意味に使っていません
  - JSON の `restore_streak_remaining_ms` も null です
- 連鎖の有効条件は成功数（`streakCount > 0`）です。受付残り（`streakRemaining`）は null のまま持ち、有効判定には使いません
  - 攻撃倍率・得点倍率・HUD・ヒビの揺れ・ステージ移行の引継ぎも、同じ判定 `streakActive` を通ります
- 失敗・成功の処理
  - 最初の失敗で切り予約（ヒビと揺れ）を立てます
  - 予約中の成功は数だけ増やし、予約は解除しません
  - 予約中の再失敗で連鎖を終了します
  - 失敗は到達時の判定イベント1回につき1回だけ数えます（反発・帰還では数えません）
  - 有効な連鎖が無い時の失敗は、従来どおり何もしません
- ステージ移行：成功数と切り予約をそのまま引き継ぎます。時間による復帰や、別の理由によるヒビ解除は入れていません
- 時間切れの処理は、受付時間を数値で明示した設定の時だけ働きます（試験で確認）。既定では起きません
- テキスト版ルール説明（採用Noto）に、依頼書の文「打上連鎖に時間制限はありません。」「役連鎖の猶予は10秒。役の処理中は止まります。」を追加しました
  - 同じページのピンチの行も、大型3/2/1の廃止に合わせて「1秒後から盤面の上に残り秒」へ更新しました

### 4.1 設定ファイル

設定は `src/data/cpu_config_fix05_mode1.json`（調整識別子 `V320-FIX-05_mode1_perception`）に分離しました。中身は表どおりの初期実装値です。

- 誤認・見落とし：難易度・状況・キャラ別
- 中級・上級の必須待ち
  - 中級：120/180/240ms、ピンチ 60/90/120ms
  - 上級：60/100/140ms、ピンチ 30/50/70ms

FIX-04 までの `cpu_config_v320.json` は変更していません（初級の必須待ち・判断時停止・最適手率・失念・4/6ピース・7個目・手動上昇）。

### 4.2 採用した方式

1. 認識（`CpuController.perceive`）：取得候補を読む時に1回だけ抽選します
   - 抽選は誤認／見落とし／正しく認識の3択を1回だけです
   - 「場のID＋各列の最上段（帰還予約を含む）」が同じ間は、同じ判断として結果を使い回します。1列移動ごと・毎フレームには引き直しません
   - 誤認：実際には合わない操作可能な最上段から1つを、認識上の候補へ加えます
   - 見落とし：実際に合う候補から1つを外します
   - 該当が無ければ変化なしです。引き直し・確率の再配分はしません
2. 同じ認識結果を、最適手の評価・ランダム選択・経路探索の入口（`shortestPaths` の最初の候補）・7個目の比較・6ピース挑戦判定で使います
3. 誤認で選んだ計画（`plan.misread`）は、発射前の成否再判定で取り消しません
   - 場のIDか対象ピースのIDが変わった時だけ破棄し、新しい判断へ進みます
   - 発射は通常の `launch` コマンドです。成否・飛行・帰還・連鎖切断はゲーム本体が判定します
   - 誤認に当たっても、その列を必ず選ぶわけではありません
4. 見落としで候補0の時は、認識した盤面に基づいて既存の打開処理（B入替・手動上昇）へ進みます。完全情報の候補へは差し戻しません
5. 確率が0%の時は乱数を消費しません
   - 初級（全キャラ・2seed）と MODE2（中級・上級）の操作列が、FIX-05 調整の有無で完全一致することを試験で確認しました
   - 中級・上級の必須待ちは MODE1 だけです
6. ピンチへの移行での半減（必須待ち・判断時停止の各1回）は、FIX-04 の処理のまま新しい表を参照します。ピンチの所要見積りも新しい必須待ちの期待値を使います

### 4.3 補足（判断）

- B入替で最上段が一周して同じ並びに戻った「再訪」は、盤面が変わった後の新しい判断として抽選します。連続する2回の抽選が同じ状態で起きないことは試験で確認しています
- 既存の CPU 試験（FIX-04 までの判断ロジックを単独で検証するもの）は、FIX-05 調整を外した設定で実行するよう更新しました。理由は各試験に記載しています。FIX-05 の調整は `tests/v320_fix05_cpu.test.ts`（9件）で検証しています

## 6. 役名の横スライドと表示時間（第6章）

### 6.1 表示

- 時系列（`RoleNameSchedule.windowsMs`）
  - 先頭は 0〜750ms（イン 0〜120・アウト 630〜750）
  - 後続は 630〜1230ms（イン 630〜750・静止 750〜1110・アウト 1110〜1230）
  - 単役は 750ms で終わります
- 各境界は宣言時刻からの ms を一度だけ tick へ換算します（区間ごとの丸めを積み上げません）
- 時間は固定です。ボイス尺・音量・デコード状態・再生可否では変わりません
  - FIX-04 までの「先頭をボイス尺まで保持」「先頭表示中の新宣言は表示待ち」は廃止しました
- 原寸・定位置のまま横に16px 動かします
  - 1P は左→右、2P は右→左です
  - イン：ease-out quadratic・透明度0→1。アウト：ease-in quadratic・透明度1→0。位置は整数px です
  - 切替中の120ms だけ2枚を描き、後続を前面にします。A/B/C の色替えは各ロゴの表示開始が起点です
- 新しい宣言は旧表示を打ち切り、新宣言の先頭から始めます。勝敗確定・ラウンド切替・メニュー・破棄でも終了します。役処理の導入1200ms は延長していません
- 実素材・1倍の描画で、各時刻の位置ずれ・透明度・2枚の重なり・静止時の素材との画素一致・終了を確認しました（`V320F05_role_slide_*ms_band_1x.png`）

### 6.2 役とボイスの一致の調査

- 対応記録：`docs/v320f05/role_voice_log.json`
  - 宣言ごとに、ロゴR番号・正式役名・代表ボイスのファイル・再生要求の時刻・各ロゴの描画開始／終了を記録しています
  - 場面：単役、数字役＋属性役、専用複合（長い音声）、代替ボイス、左右同時、同じプレイヤーの次の宣言、相手の宣言の割込み、勝敗の割込み、ボイス無効
- コード上の対応
  - ロゴ R01〜R16（役一覧の正式名の順）とボイス `role_01`〜`role_16` は番号どおりです
  - 先頭ロゴと代表ボイスの要求は同じ宣言 tick です。複数役でも代表は1本、代替（攻撃）ボイスとは同時に鳴りません
- 素材の尺（事実）：3キャラとも、名前が長い役ほど音声が長い傾向でした（例：R16 スーパーストレートフラッシュが最長、コタロー 3.48秒）
  - 例外：コタローの role_14（ストレートフラッシュ、2.83秒）が role_15（ハイストレートフラッシュ、2.54秒）より長いです
  - 番号ずれの可能性は低いと推測しますが、聴いて確かめていません（未確認）
- 仕組み上の不一致の原因（再現条件つき。聴感では未確認）
  1. **相手の宣言が自分の読み上げを切る**
     - 左右の役名ボイスは同じ再生チャンネル・同じ優先度（30）で、後から来た声が先の声を止めます
     - 1Pの宣言から約0.35秒後に2Pが宣言すると、1Pの画面は1Pの役名ロゴのままで、聞こえるのは2Pの役名です
     - 記録の場面「相手の宣言が自分の表示中に入る」で、1P のフォーカード表示中に 2P の「フラッシュ」の再生要求が出ています
     - 音声優先度全体は依頼書の指示どおり変更していません
  2. **表示が先に進み、読み上げが残る**
     - 固定時間（先頭750ms・後続は630msから）より長いボイスでは、後続ロゴの表示中も先頭役の読み上げが続きます
     - 例：コタロー フォーカード 1.31秒 → 630〜1310ms は「フォーブラック」表示中に「フォーカード」が聞こえます
     - 依頼書が指定した固定時間の仕様どおりの動作です
  3. 代替ボイス（20%）は役名ではなく攻撃ボイスなので、役名ロゴと言葉は一致しません（従来仕様）
- 同じプレイヤーは役処理（導入1200ms以上）中に次の宣言ができません。そのため、表示全体（最大1230ms）の途中に自分の新宣言が入る場面は、本編では起きません
