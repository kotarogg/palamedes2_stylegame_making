### 3.2 ランダム打上げ（実験と同じ挙動）

- **判断の順番**：宣言判断 → 既存の手動上昇 → 新規取得判断（7個目の追加取得を含む）の順です。ランダム打上げは新規取得判断の中で抽選します。
- **候補**：発射可能な最上段がある列から一様に選びます。空列と、最上段が予約の列は候補外です。適合・役・距離・猶予では選別しません。
- **抽選機会**：場のID、各列の最上段のID（発射不能は「-」）、手役IDの組で識別し、同じ機会は1回だけ抽選します。非移動操作を出したら次の機会に移ります。候補が無いときは抽選しません。
- **選んだ後**：場が変わっても成否で取り消しません。失念停止の後も、選んだ列を保持します。物理的に発射できなくなった場合だけ、取り消して通常の再判断に戻ります。
- **乱数**：専用の seeded stream（`(Math.imul(seed,2654435761)+Math.imul(player+1,1013904223))>>>0`）と `randomInt` を使います。既存の乱数列は消費しません。0％のときは専用乱数も消費しません。
- **ラウンド境界**：抽選機会・計画・R1 の履歴を初期化します。専用乱数の系列は続けます。
- **検証用の記録**：`stats` に、抽選機会、当選（hit）、発射命令、選択時の適合（診断のみ）、失念保持、物理的取消を記録します。
  - `randomLaunchLog` には発射命令の tick・ピースID・列を記録します。実際の発射・到達・成否は、ゲームのイベントと照合します。
  - 強制的な発射・到達や、試合の延長は行いません。

### 3.3 R1 列入替

- **対象**：ランダム打上げを使わず、通常取得の候補も無いときだけです。適合する2段目があり、2段以上で予約の無い列が候補です。3段目以降は探索しません。
- **選択順位**：移動＋入替＋再判断＋取得の予想時間が短い列を選びます。同じ値なら近い列、さらに同じなら列番号の小さい列です。
- **回数**：場のID・各列のピース集合（順序によらず、予約を区別）・手役IDが同じ間は1回までです。既に訪れた盤面に戻る入替もしません。
- **計画の取消**：場が変わった、予約ができた、通常取得の候補が復活した、対象の2段目が不適合になった場合は、計画を取り消して通常判断に戻ります。
- **入替できないとき**：適合する入替が無ければ、従来どおり合法な手動上昇を行います。それもできなければ待機します。
- R1 が無効な難易度・モードでは、従来の打開（`recoverDefault`、内容は変更なし）を使います。

### 3.4 FIX01 の見積りと QA-01

- **所要時間の計算**（候補選定と再評価で同じ関数 `r1OpsMs`／`r1InTime`）
  - 操作時間：`opsMs = acquireMs(現在列, 対象列) + depth × rotateMs`
  - 選択順位用の時間：`opsMs + depth × (必須待ち＋判断停止の期待値)`
  - ピンチで間に合う条件：`pinchNeedMs(opsMs,1) + (depth−1)×判断待ち < 残り猶予`（R1 は depth＝1）
  - 判断待ちは `pinchNeedMs` 側の1回だけです。順位用の時間（判断待ちを含む）を `pinchNeedMs` に渡すことはありません。
- **QA-01**：入替計画は、移動の途中（各移動の合間）、到着時、入替命令の直前に再評価します。使う値は次のとおりです。
  - 最新の現在列と対象列（既に済んだ移動は数えません）
  - 有効な残り猶予と、未消化の待ち
- 通常からピンチに変わった場合も、再評価の対象です。必要時間が残り猶予以上なら計画を取り消して通常判断に戻ります（上昇は強制しません）。
- 猶予が十分なら、再抽選も待ちも追加せずに入替に進みます。
- 取り消した回数は `stats.r1PinchCancels` と、`log` の `r1PinchCancel` に記録します。既存のピンチ猶予での停止・半減の仕様は変えていません。
