## 4. CPU設定ファイルと全初期値、判断・抽選のタイミング

- 設定ファイルは `src/data/cpu_config_v310.json` です。全初期値は指示の表どおりで、単体テストで全項目を照合しています。
- 表と判断のタイミングの全文は `docs/CPU_CONFIG_V310.md` にあります。

要点：

- 確率は0〜100%、時間はmsで、意味を設定ファイルの `units`・`notes` に明記しています。
- 乱数は CPU ごとの seed 付きで、試合の乱数とは別系列です。抽選は判断機会ごとに1回で、毎フレーム再抽選しません。
  - 同じ seed なら判断が一致することを単体テストで確認しました。
  - 0%・100% の場合も乱数を1つ消費します。設定値を変えても、以後の乱数列の位置がずれないようにするためです。
- 抽選の単位：
  - 宣言・挑戦：手元（役ストック）または通常／ピンチの状態が変わったとき。
  - 目的地なしの停止：目的地を探す機会ごと。
  - 失念：移動計画ごと。移動開始後の最初の判断時点で適用し、同じ移動機会では再失念しません。停止と重ねません。
  - 手動上昇：見送ったら、盤面・手元が変わるまで再抽選しません。
- ピンチ：「取得経路の所要時間＋宣言から解除まで（役の導入700ms＋1tick）＋判断余裕 ＜ 有効な残り猶予」を満たす経路だけを採用します。
  - 取得だけで期限を超える候補は除外します。
  - 6ピース役が間に合わず、今の成立役で助かる場合は宣言します。
- 探索の深さは、今回必要な残り取得数に限定しています（最大4）。

## 6. 発見したバグ・注意点

1. **自然上昇の危険猶予と数字の不整合（判断待ち）**
   - 再現条件：7段のまま自然上昇の時刻になる。
   - 原因：自然上昇の危険猶予は3000msのままです（今回の指示の対象外）。有効な残り猶予に同期する仕様のため、到達時点で残り3000ms＝「3」がすぐに出ます。攻撃ピンチは指示どおり1000ms後に「3」です。
   - 対応：期限を後から延ばして生存できる挙動にはしていません（早い期限を採用。単体テストで確認）。
   - 選択肢：
     - (A) 現状のまま
     - (B) 自然上昇の危険猶予も4000msにする（ルール変更のため要判断）
     - (C) 数字は攻撃ピンチだけに出し、自然上昇は「危険 x.x秒」だけにする
2. **READY／GO の見出しと中央ストック列が重なる**（表示上の注意。修正なし）
   - 再現条件：ラウンド開始時。
   - 原因・判断：見出し（x240〜400、y144〜208）が中央の列と重なります。表示は開始時の短時間だけで、新ラウンドではストックが空なので実害はないと判断しました。ブラウザ検査は GO 終了後に描画を確かめるよう変更しています。
3. **CPU の打ち上げミスの大半は、飛行中に共通基準が変わったことによる**
   - 測定：中級3試合74件のミスのうち71件は、打ち上げ時点では成功する候補でした。残り3件は、同じtickに相手の到達で基準が先に変わり、古い基準で判断した1tickの差です。
   - 意図的なミスはありません。改善はルールの外側（先読み）になるため、変更していません。
4. **既存検査の固定待ち・前提の更新**
   - CPU戦がキャラ選択を経る流れ、PNG数（49→58）、結果SEの時刻、代替ボイスに合わせて、ブラウザ検査を更新しました。
   - 「未来ピースを参照しない」検査は、手動上昇で新しいピースが出る前までを比較するよう変更しました。
5. 未解決のバグはありません（判断待ちは上記1）。

## 7. 仕様との差分・実装上補った判断・品質向上の変更

- **CPU の速さ**：旧CPUの反応時間・移動間隔（初級700/220msなど）は「処理内に埋め込んだ待ち」だったため削除しました。待ちは表の停止（目的地なし・失念）だけで、`actionGapMs`＝0 です。
  - 結果として CPU の操作は旧版より速くなりました。
  - 移動・打ち上げの速度（ゲーム側）は変えていません。
- **CPU の補った判断**：
  - 6ピース役へ挑戦中は、手動上昇の抽選より取得目標を優先します。
  - 手元0〜2は「役（4ピース以上）を作る最短経路」、手元4〜5で役なしは「成立可能な役への最短経路」を目指します。手元6で役なしは押し出しを含め最大2取得を探索します。
  - 候補がないときは、2段目B入替 → 3段以上B入替 → 手動上昇 → 盤面の変化待ち、の順に打開します（既存の合法手段）。
  - 4ピース役で宣言を見送った後は、役を維持できて翻数が高い取得を最適とします。
- **CPU戦**：結果メニューに「キャラ選択へ」を追加しました（指示の「キャラ選択へ戻る場合」を実現するため）。
- **開始前待機**：画面側（GameScene）で実装しました。ゲームの時計（tick）を止めるため、READY・タイマーは待機後に始まります。単体のゲーム処理（core）は変更していません。
- **連鎖切り予約**：
  - シングルの次面へ連鎖を引き継ぐ場合は、予約も引き継ぎます（連鎖が終わっていれば引き継がない）。
  - 受付時間切れで成功数を0にしました。シングルの引継ぎは従来も「受付時間内の連鎖だけ」なので、挙動は変わりません。
- **ヒビの選択**：試合の乱数を消費しないよう、予約発生のtickとプレイヤー番号から3種を決めています。予約中は固定です。
- **ヒビの表示**：倍率には付けず、成功数の数字にだけ付けます。合成画像は数字・位相・ヒビごとにキャッシュし、毎フレーム生成しません。
- **連続出しの見出し**：原寸80×20、役連鎖の見出しは1/2（48×12）です。役連鎖は連鎖数34pxで目立たせています。見出しの大きさの比較はPMの評価が必要です。
- **ゲーム処理に影響しない表示用イベントの追加**：`pinchWarn`、`streakCut`、`allClear.stageClearPending`。
- **宣言SEの −2dB**：役名表示の予定から、代表ボイスが宣言と同時に始まるかを判定しています（前の役名表示の待ち中は0dB）。
- **ピンチボイス**：優先度を最も低くしています（勝敗・READY・GO を中断しない）。鳴らせなければ捨てます。
- **相殺音**：`attack.counter.canceled` を唯一の発音元のまま維持しました。`attackCancel` は表示用なので鳴らしません。単体テストで相殺の件数と一致し、二重・欠落がないことを確認しています。
- **MODE2**：ミス帰還の降下1.6倍は MODE1 と設定を共有するため、MODE2 にも適用されます。MODE2 の場の更新周期・カウントダウンは変えていません。
- **英文**：残る英文見出し（GAME OVER、STAGE CLEAR、ALL STAGES COMPLETE、ALL CLEAR、READY、GO、LEVEL UP、MAX）は変更していません。意味は伝わると判断しますが、日本語化するかはPM判断です。
