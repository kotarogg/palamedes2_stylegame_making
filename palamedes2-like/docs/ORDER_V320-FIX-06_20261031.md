# 1．目的と作業範囲

  

今回の目的：

・連鎖に頼らず、単発の役でも立て直しと攻撃ができるようにする。

・相殺効率を下げ、防御によって試合が終わらない状態を改善する。

・CPUの操作速度を難易度別に制限し、人間との操作速度差を調整する。

・遊び方の実演を完全自動で開始し、実際の処理完了と最低表示時間に従って進行させる。

・受ストックのアイコン横に表示する数量数字を削除する。

  

本書の数値は確定値です。計測結果を理由に独断で再調整しないでください。

比較基準より後の変更がブランチに存在する場合は、その変更を保全してください。開始時点と納品時点のコミットを報告してください。古いコミットへの強制リセットや無関係な変更の巻き戻しはしません。

ゲーム本体のバージョン番号は上げません。今回の修正段階はV320-FIX-06で識別してください。

  

# 2．役の数値管理と確定表

「消去」は自フィールドの予定消去ライン数。「基本攻撃」は両連鎖加算・相殺前の攻撃ライン数です。

旧仕様の「翻数＝消去数」「翻数−1＋数字役ボーナス」を新計算に流用しません。表へ旧数字役ボーナスをさらに加えることは禁止です。旧翻数を同点時の順位等に残す場合は用途を区別してください。

# 3．役の自動採択と表示整合

  

優先順：

① 6個全体で役が成立すれば優先する現行規則を維持。

② 同じ選択段階では、新しい表の消去数が多い候補。

③ 同数なら基本攻撃数が多い候補。

④ 両方同じなら数字役の従来の強さ→既存役一覧順。

⑤ 完全同点なら先に列挙された集合。

  

4個はその集合、5個は4個を選ぶ全5通り、6個全体で成立しない場合は4個を選ぶ全15通りを評価してください。

成立光・宣言結果・役名表示・代表ボイスの選定元は同じ採択結果を参照してください。

表示順は数字役→属性役、専用ストレートフラッシュ系は1ロゴを維持。FIX-05のスライド距離・表示時間は変更しません。

宣言時に採択外を含む手役ストック全体を消費する現行動作を維持してください。

  

# 4．連鎖による攻撃加算

  

4.1 打上連鎖

  

旧攻撃倍率を廃止し、固定加算へ変更：

0〜4連鎖：＋0

5〜9連鎖：＋1

10〜99連鎖：＋2

  

カウント上限99。99到達後も成功時は99を維持し、攻撃加算は増えません。

時間経過では切れません。有効な連鎖中の1回目の失敗で切断予約。予約後に成功しても予約・ヒビは残り、予約中の次の失敗で切断します。

同じ失敗の跳ね返り・帰還で二重計上せず、連鎖がない状態ではヒビ付き0連鎖を作りません。

ヒビと揺れ、ラウンド終了時のリセット、ステージ移行時の成功数・予約の引き継ぎは維持。

シングルの得点倍率は変更しません。攻撃加算と混同しないでください。

  

4.2 役連鎖

  

現行維持：

1連鎖：＋0、2連鎖：＋1、3連鎖：＋2、4連鎖：＋3、5連鎖以上：＋4。

受付10,000ms、成立宣言で更新、自分の成立役処理中は停止、ステージ移行で最大復帰。

  

4.3 計算式

  

通常攻撃力＝基本攻撃数＋打上連鎖加算＋役連鎖加算。

最大値＝8＋2＋4＝14ライン。

採択役・両連鎖加算は宣言時点で確定し、処理途中の変化で再計算しません。

自フィールドの消去数は連鎖の影響を受けません。盤面不足では存在する分まで消去しますが、攻撃数は減らしません。

  

# 5．相殺を1対1へ変更

  

通常攻撃力1で、次ブロック待機分1ラインを相殺します。相殺に使わなかった攻撃力だけを相手へ送信。

相殺対象は次ブロック待機分のみ。現ブロック未消化分・進行中の波・消費済み表示予約枠は対象外。消失演出中の残像は内部数量へ含めません。

  

例：

攻撃3・待機0：相殺0、送信3、待機残0。

攻撃3・待機1：相殺1、送信2、待機残0。

攻撃3・待機3：相殺3、送信0、待機残0。

攻撃3・待機5：相殺3、送信0、待機残2。

  

維持する事項：

受ストック上限29。ブロック終了までの表示枠予約。現ブロックと待機分の分離。ピンチ時の波の余剰破棄。段周期400ms。ブロック間2,000ms。ピンチ猶予4,000ms。警告開始は1,000ms後。双方同時送信の処理順で有利不利を作らない。

  

# 6．CPUの難易度別操作速度

  

MODE1・MODE2共通。人間側の移動速度・先行入力・パッド反復を変更しません。

60tick/秒でtick数を正本としてください。

  

初級：移動開始間隔の最短12tick（200ms）、最終移動完了から打上まで最低6tick（100ms）。

中級：移動開始間隔の最短9tick（150ms）、最終移動完了から打上まで最低4tick（約66.7ms）。

上級：移動開始間隔の最短7tick（約116.7ms）、最終移動完了から打上まで最低2tick（約33.3ms）。

  

実装条件：

・間隔は前回の移動開始→次の移動開始。移動完了後に12／9／7tickを丸ごと追加しません。

・同方向・反転・目標再選択も対象。再計画で制約を迂回しません。

・初回移動には架空の前回移動による待ちを作りません。

・最初から目的列にいて移動していなければ、移動後の追加待ちは不要。

・再判断のたびに同じ到着待ちを最初からやり直しません。

・判断停止・操作間隔・操作硬直は並行して進み、全条件を満たしたら操作可能。同じ待ちを重複加算しません。

・ピンチでも操作間隔は同じ。既存の判断待ち半減のみ維持。

・待機中の入力蓄積、同じ操作の重複発行を防止。

・新ラウンド・新試合・画面作り直しで操作履歴を初期化。

  

既存の必須判断待ち、確率停止、失念、最適手選択率、キャラクター差、探索深さ、認識ミス設定は維持します。設定値は調整可能な共通データで管理してください。

  

CPUの役判断：

・新しい消去数・基本攻撃数で比較。

・7個目取得の改善判定は、消去が増える、または消去が同じで基本攻撃が増える場合。

・6／7ピース挑戦等のピンチ所要見積りへ、新しい移動間隔・打上待ち・未消化の待ちを含める。

・挑戦確率の便乗変更、勝率を合わせる補正は入れない。

  

# 7．遊び方・実演の完全自動進行

  

7.1 開始と進行

  

「決定で実演へ」を廃止。項目へ入ったら説明表示と実演を自動開始し、その時点を経過時間0とします。

次項目への移行条件は「その実演に属する全処理完了」かつ「項目開始から最低表示時間が経過」です。

実演途中に最低表示時間のための停止を挟みません。実演終了後に最低表示時間を丸ごと待ち直しません。

  

最低6秒の例：

実演が開始2秒後に完了→残り4秒だけ待機→開始6秒後に次へ。

実演が開始6秒後に完了→追加待ちなし。

実演が開始9秒後に完了→9秒の完了直後に次へ。

文字説明だけなら最低表示時間で自動進行。

  

7.2 全処理完了の定義

  

最後の操作命令を送った時点ではなく、実演に属する処理を状態で判定してください。

移動、打上飛行、跳ね返り・帰還、上詰め・列入替、役宣言・役名スライド、ライン消去・足場移動・攻撃、締めの演出、必要なクリア・ミス処理等が対象です。

全ゲームタイマーや常時アニメーションを待つのではなく、項目ごとに必要な終了条件を定義。

BGM・待機モーションは完了を妨げません。ボイス尺・ミュート・デコード状態へ進行時間を連動させません。音声は既存優先順位で扱い、説明移行を理由に一律強制停止しません。

  

実演完了後に最低時間の残りを待つ場合、完了画面と説明を維持。自然上昇やCPU操作が次の動作を始めて説明と盤面が食い違わないよう、実演制御側で終了後の進行を止めます。

  

7.3 最低表示時間

  

初期値＝max（3秒、1秒＋説明本文の文字数÷8秒）。

句読点を数え、空白・改行・常設操作案内を除きます。tick換算は切り上げ。

試遊後に変更しやすい項目別設定にします。この値は初期調整値であり、読みやすさの検証済み値ではありません。

実演途中で説明を切り替える場合、切替ごとに最低時間を加算して停止しません。文章ごとの表示時間を記録し、短すぎる部分を報告してください。

  

7.4 入口・出口

  

遊び方メニューから：説明と実演を自動進行。キャンセルで遊び方メニューへ戻る。

オプション「デモ再生」から：新しい操作入力でタイトルへ戻る。

タイトル放置デモ：新しい操作入力でタイトルへ戻り、放置時間をリセット。

入場の決定入力を持ち越して即終了させません。入場時の押下は一度離してから新規入力として受け付けます。

放置デモの暗転中も、タイトルへ戻れる案内を表示。

進行に決定入力を要求しません。役一覧・操作一覧の閲覧UIまで無関係に自動送りへ作り直しません。

  

7.5 教材配置の再検証

  

消去数変更で後の教材ピースが消える可能性があります。固定配置・供給・操作台本を再実行し、開始から全処理完了まで確認してください。

維持する教材の意図：

・4／4／6ピースの連続取得。

・2回目は数字がばらばらの4ピースフラッシュ。

・3回目はフルカードまたはスーパーストレート。

・役連鎖1→2→3。

・打上失敗と帰還。

・MODE2は全ピースを出し切り、クリア処理・説明完了まで再生。

  

必要な供給・手動上昇を教材側へ組み込んで構いません。宣言による実消去、未使用のまま消えるピースも検証。

成功数・連鎖数・クリア状態の直接書換えで成立を偽装しません。MODE2説明を放置デモへ追加する範囲拡大もしません。

  

# 8．受ストックの数量数字削除

  

受ストックのネコタローアイコン横の数量数字を1P・2Pとも削除。

維持するもの：

・小アイコンと5ライン分の大アイコン。

・現ブロックの囲い・点滅。

・待機分との分離、上詰め。

・相殺時の顔・小爆発・160ms消失演出。

・ブロック開始時等の演出打切り。

・内部数量・予約枠・上限29。

  

攻撃送信量・相殺結果の別演出数字、連鎖数、MODE2残りピース数等まで削除しません。

  

# 9．変更しない事項・素材不足

  

新しい役消去数はMODE1シングル・対戦共通。シングルの攻撃送信なしを維持。

ステージノルマ・レベル条件・得点単価・得点倍率・ボーナス表は変更しません。実消去1ライン＝6ピース換算を維持し、進行速度への影響は報告。

MODE2はCPU速度と共通説明処理以外のルールを変えません。

対戦ノルマは導入しません。役連鎖10秒、ピンチ4秒を維持。

音声再制作・BGM差し替え・全体のボイス優先順位変更は範囲外。

  

役一覧・説明・デモの数値を更新し、旧攻撃倍率の説明を残さないでください。

現時点では新規画像・音を前提としません。欠字等が見つかれば発生箇所・必要素材・表示例を報告。無断の代替文字・不自然な縮小で隠しません。

  

内部設計・状態管理・表示整合の方法はプログラマの判断に委ねます。確定した数値・ゲーム動作を変える必要がある矛盾は再現条件・影響・推奨解決案を報告。仕様どおりではバグると分かって黙認したまま納品しません。

  

# 10．必須検証とバランス計測

  

10.1 正しさの検証

  

・単独役15行／複合役28組が表どおり。色の大小役、属性二重加算防止、専用ロゴ3種。

・新自動採択と、成立光・表示・代表ボイス選定元の一致。

・打上4→5、9→10、98→99、99以降。予約が成功で解除されず次の失敗で切れる。

・最大攻撃14。旧倍率・旧ボーナス残存なし。

・盤面不足の消去打切りと攻撃維持。シングルの実消去に対応した得点・ノルマ。

・相殺1対1、現ブロック非対象、同時送信、上限29・予約枠。

・難易度別実移動開始tick差、到着後打上tick差。反転、再計画、初回、初期位置打上、ピンチ、次ラウンド。

・ピンチ所要見積りに新しいCPU待ちが入る。

・実演が最低時間より短い／同じ／長い場合、文字のみ、台本終了後に帰還・役スライドが残る場合。

・教材と説明の一致、MODE2クリアまでの完走。

・左右の受ストック数字が消え、アイコン・相殺演出が残る。

  

型検査、必要な単体・回帰テスト、ビルド、ブラウザ検査を手元で実施。旧仕様の期待値を更新したテストは変更理由を説明。

正常終了した同じ検査を理由なく反復しません。修正・失敗・未解決事項がある場合は影響範囲を再検査。

  

10.2 MODE1計測：計45ラウンド

  

各難易度につき、同難易度のコタロー対アカネ／アカネ対ずん子／ずん子対コタローをseed1〜5で実行。1ラウンド180秒上限。

記録：決着時間・原因・勝者・未決着、役内訳・宣言間隔、打上／役連鎖最大値、基本攻撃・連鎖加算・相殺・実送信・盤面適用量、上限超過／ピンチ破棄量、ピンチ回数・復帰回数。

未決着を除外した平均では対象件数と未決着件数を併記。

  

10.3 MODE2計測：計45回

  

各難易度×各キャラクター×seed1〜5でシングル。seedが同じなら同じ初期盤面・条件で比較し、その識別情報を記録。

クリア時間の平均・中央値・最短・最長・標準偏差、完走／未完走件数、場更新回数、実移動・打上間隔を報告。

通常CPUで実行し、測定用の必勝処理を入れません。CPU成績を人間の勝率と同一視しません。

明らかな不具合は全件を無駄に回さず修正し影響範囲を再計測。結果が悪いという理由だけで確定値を変更しません。

  

確認画像は役一覧、複合役結果、左右受ストック数字非表示、説明実演の開始／完了／移行など必要最小限。

聴感・実パッド・人間の遊びやすさは、確認していなければ未確認と報告。
