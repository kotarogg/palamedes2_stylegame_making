## 3. 仕様整合のための実装判断（自己判断による仕様変更はなし）

1. **旧翻数の扱い**：数字役の旧翻数（1/1/1/2/3/3/3）は `LEGACY_NUMBER_STRENGTH` として、採択の第4順位「数字役の従来の強さ」にだけ使います。消去・攻撃の計算には使いません。
2. **打上連鎖数のスナップショット**：宣言時の打上連鎖数を役処理に保持し、攻撃処理で加算を計算します（宣言後の成功・失敗で再計算しない）。宣言イベントには加算値（streakBonus）も記録します。
3. **CPU の待ち方**：移動・打上を見送る間も計画（目的列・抽選結果）を保持し、待ちは絶対tick（前回の移動開始tick、最終移動の完了tick）で判定します。これにより判断停止・必須待ち・失念・操作硬直と並行に進み、再判断で待ちがやり直されず、二重加算もしません。「直前の打上以降に移動したか」で打上待ちの要否を判定します。
4. **7個目の改善量**：`roleRank＝消去×100＋基本攻撃` の差で比較します（消去が増える、または消去同じで基本攻撃が増える場合だけ改善）。
5. **ピンチ所要見積り**：n歩の取得＝（n−1）×max（移動1歩, 移動開始間隔）＋移動1歩＋打上待ち＋発射＋上詰め。未消化の待ちには移動開始間隔の残りも含めます（判断停止の残りと並行のため遅い方）。
6. **実演の完了判定**（項目ごと）：飛行（打上・跳ね返り・山なり・下降帰還）・移動・上詰め／入替／不成立の硬直・役処理（宣言〜消去・足場移動・攻撃・戻し）・手動上昇の途中でないこと。決着後は結果演出の受付可能時刻まで（GAME OVER／MODE2クリア処理）。MODE2 はカウントダウン・場の更新の演出中でないこと。BGM・待機モーション・ボイスの尺は条件に含めません。役名スライド（FIX-05：最大1230ms）は役処理（導入1200ms＋消去＋締め500ms）の内側で終わるため、役処理の終了待ちに含まれます（検査で確認）。
7. **最低時間の残りを待つ間**：ゲームを1tickも進めず（自然上昇・猶予・CPU・ゲーム時計が止まる）、完了画面と説明を保ちます。項目の時計は舞台の tick（1/60秒）で数えます。
8. **複数パネルの頁**：最低表示時間を各パネルの文字数で按分した時刻にパネルを切り替えます（切替ごとに時間を加算しない）。最後のパネルは項目の終わりまで表示。
9. **遊び方の最後**：全舞台の再生後の「もう一度／戻る」の選択は進行ではなく終了後のメニューとして残しました（決定入力を要求する進行はありません）。
10. **教材の盤面**（4/4/6）：第6節 不具合1を参照。
11. **対戦デモ seed**：新ルールで旧 seed 5 が既存の選定基準（両者送信・攻撃段10超・相殺4回以上・60秒以内決着）を満たさないため、seed 1〜300 を同じ基準で選び直し最小の 6 を採用しました（攻撃段31・相殺5・約58.7秒）。

## 8. PM判断事項・残課題

1. **上級CPU同士の長期化**（第7.3節）：確定値・CPU設定は変更していません。対策の候補（例：役連鎖の受付短縮、上級の判断待ち増、相殺の扱い）はPM判断事項です。
2. **役一覧の表示値**：オールマーク・フラッシュは役一覧の実例が4個のため、4個の値（2/2・3/2）だけを表示しています。6個の値（3/3・4/3）を併記するかは判断事項です（新しい文字列・配置が必要）。
3. **打上連鎖の加算表示**：連鎖HUDは役連鎖の「＋N」だけを表示し、打上連鎖の加算（＋1／＋2）は表示していません（指定なし）。
4. **説明文**：「打上連鎖をつなぐと、得点倍率と対戦での攻撃力がアップ！」は倍率の数値を含まないため変更していません。5連鎖・10連鎖の段階を説明に加えるかは判断事項です。
5. **複数パネルの頁の表示時間**：按分の結果、パネル単独では初期式より短いものがあります（第9節の表の「パネル表示」）。特に短いもの：m1_versus 1枚目 1.98秒、streak_crack 2枚目 1.75秒、limit 2枚目 1.90秒、role_ready 各2.75秒（実演中）。値は初期調整値です。
6. **放置デモの章の切替**：暗転の黒の時点での効果音停止（既存）は残しています。
7. 聴感・実パッド・実機での確認は未実施です。

### 実機試遊の重点

- 単発役（2〜4ライン消去）での立て直しの手応え、オールマーク等の小役の多用感。

## 10. ビルド・起動・検査の手順

作業ディレクトリ：`palamedes2-like/`（Node.js 22 系、`npm ci` 済み）

1. 型検査：`npx tsc --noEmit -p .`
2. 単体テスト：`npx vitest run`
3. ビルド：`npm run build`（`dist/`）
4. ブラウザ検査（Playwright・Chromium）：
   - `node scripts/e2e.mjs`（正式素材を配置した場合）／フォールバック時は `E2E_FONT_STANDIN=<代替フォントのディレクトリ> node scripts/e2e.mjs --fallback`
   - `node scripts/e2e-fix04.mjs`、`node scripts/e2e-fix05.mjs`、`node scripts/e2e-fix06.mjs`
5. 計測：`npx vitest run --config tools/vitest.measure.config.ts tools/cpu-fix06.measure.ts`（出力 `docs/v320f06/measure/`）
6. 配布物の組み立てと検査：`npm run assemble:play -- <出力先>` → `node scripts/check-release.mjs <出力先>`（BGM未配置なら `--allow-missing-bgm`）
7. 起動：配布物の `start-windows.bat`（Windows）または `start-mac-linux.sh`、開発時は `npm run dev`

必要素材の配置先：正式BGM 3本 `public/assets/audio/bgm/`、本文フォント `public/gfx/fonts/NotoSansJP-VF.ttf`（いずれも今回の手元検査では未配置）。
