# 第1章　ゲームの基本構想

## 1.1 目的

ファミコン『パラメデスII』を参考にした、16bit時代の対戦パズルゲームの雰囲気を持つブラウザゲームを制作する。

単純な数字合わせだけでなく、役の成立、役宣言、連鎖、攻撃と相殺による競争を中心にする。

原作を参考にするが、原作の完全再現ではない。独自に決定したルールを正式な仕様とする。

## 1.2 実装環境

- Windows上で開発。
- ブラウザで実行するゲーム。
- 論理解像度640×360。
- 16:9。
- 16bit風ピクセルアート。
- ローカル2人対戦とCPU対戦を想定。
- 将来的にオンライン対戦を検討。

TypeScriptとPhaserは技術候補だが、具体的な採用はプログラマーが既存構成と照合して決定する。

## 1.3 モード

### MODE1 MATCH

初期ピース18個、6列×3段を基本とする対戦モード。

役、攻撃、相殺、勝敗の仕組みを使用する。

初期ピースは盤面下側の3段に配置する。

### ひたすらモード

初期ピース42個、6列×7段。

役による対戦攻撃を使用しない単独プレイを想定する。

### MODE1 SINGLE

原作の動作参考資料として使用する。

ユーザーが撮影したBボタン入れ替えの3画像は、原作のMODE1 SINGLEである。

SINGLEの独自UI、SPEED表示、得点表示を、今回のMATCH画面へ無条件に転用してはならない。

### その他

QUEST等の発展モードは将来対象。最初のテスト版では優先しない。

# 第2章　フィールド

## 2.1 基本構造

プレイヤーごとに独立したフィールドを持つ。

- 横6列
- 縦7段
- 1セル32×32
- フィールド192×224
- 列インデックス0～5
- 行インデックス0～6

全プレイヤーで共通の基準ピースが、画面中央上部に1個存在する。

## 2.2 ピース種類

数字1～6と、属性4種類の組み合わせ。

属性は以下の4種類。

- ♠：スペード
- ♦：ダイヤ
- ♣：クラブ
- ♥：ハート

合計24種類。

同じ種類のピースが複数生成されてよい。

生成確率は原則として24種類均等。

## 2.3 ピース配列

列内のピースには上下の順序が存在する。

発射や入れ替えの対象は、その列の**最上段のピース**。

成功後の列の詰め直しは上方向。

ピースを発射した時点では、失敗帰還の可能性があるため、すぐに詰めてはならない。

フィールドの論理配列、描画座標、移動中ピース、予約空白は独立管理する。

# 第3章　共通基準ピースと打ち上げ

## 3.1 共通基準

画面中央上部の基準ピースを1P・2Pが共有する。

基準ピースには数字と属性がある。

両者は同じ基準に対して自分のピースを打ち上げる。

## 3.2 成功条件

次の条件のいずれかを満たす場合は成功。

1. 数字が一致。
2. 数字が隣接。
3. 属性が一致。

数字の隣接は循環する。

したがって、1と6も隣接している。

成功判定は、以下と等価。

```text
成功 =
    数字が一致
 OR 数字の差が1
 OR 数字の差が5
 OR 属性が一致
```

## 3.3 発射動作

現在選択している列の最上段ピースを打ち上げる。

ピースは現在位置から共通基準ピースの中心へ直線移動する。

移動はTWEEN。

発射位置・列・距離が違っても、**直線打ち上げに要する時間は同一**。

したがって、移動距離によって表示速度が変わる。

移動時間の具体的なミリ秒数は未確定。テスト用設定値に分離する。

## 3.4 判定時刻

成功判定は**ボタンを押した時点ではなく、共通基準へ到達した時点**で行う。

発射時に成功が見込めたピースでも、その後に他プレイヤーが基準を変えれば、失敗することがある。

逆に、発射時点で条件不一致のピースが、到達時には成功することもある。

## 3.5 同時到達

複数ピースが基準に向かっている場合、到達した順番で判定する。

成功すると基準ピースを即座に更新する。

後から到達したピースは、更新後の基準ピースで判定する。

**同一フレーム到達の場合は1P優先。**

描画FPSではなく、ゲームロジック側のフレーム・イベント順序で確定する。

## 3.6 打ち上げ成功

成功すると以下を処理する。

- 基準ピースを打ち上げたピースへ更新。
- 成功ピースを発射プレイヤーの役ストックへ追加。
- 発射元列の帰還予約を解除。
- 残った列ピースを上方向へ詰める。
- 残留ピースの移動はTWEEN。

成功ピースが基準位置へ到達した瞬間に、基準ピースと重なって表示されることは許可する。

## 3.7 打ち上げ失敗

基準に到達して不一致なら、ピースは元の列へ帰還する。

帰還は瞬間移動ではない。

以下の順序で処理する。

1. 基準ピースへ直線TWEENで到達。
2. 短い反発エフェクト。
3. 高速の山なり曲線TWEEN。
4. 元の列Xへの到達。
5. 低速の垂直TWEENで下降。
6. 予約位置へ帰還。
7. 最終位置をSNAP補正。
8. 列の操作ロック解除。

曲線の到達点Y=76は画面設計で補完した暫定値。

高速曲線と低速下降は別々の移動時間を持つ。

### 帰還先の予約

発射元の位置を予約空白として保持する。

帰還待ちの予約空白は通常の空きセルではない。

帰還待ちの列では、新しい打ち上げとBボタンの列入れ替えを禁止する。

**他の列の操作は継続できる。**

### 盤面上昇との競合

予約空白は盤面の一部として扱う。

自然上昇・手動上昇で盤面が上がると、予約空白も一緒に上がる。

山なり曲線の区間では、帰還先の変化を追跡して曲線を変更する必要はない。

しかし、**低速下降中は、予約空白の現在Yを毎更新で再計算する**。

重要条件：

**盤面の上昇によって帰還距離が変わっても、低速下降の所要時間を変更しない。**

下降開始時刻と終了時刻を固定し、その間の表示速度を調整する。

下降完了時には最新の予約位置へSNAP補正する。

帰還ピースと予約空白を二重に実体化させてはならない。

# 第4章　Bボタンによる列入れ替え

## 4.1 操作の目的

選択列の最上段ピースを、同じ列の最下段へ移す。

その他のピースは一つずつ上へ詰める。

## 4.2 ピースの移動

最上段ピースを暗色表示へ変更。

そのピースは**通常列ピースの背面**を通る曲線移動で最下段へ到達する。

残りのピースもそれぞれTWEENで新しい位置へ移動する。

暗色ピースが目的地に到達すると、通常色へ戻る。

全ピースを一度に瞬間移動してはいけない。

## 4.3 キャラクター演出

Bボタンを押した瞬間、キャラクターの立ち絵を攻撃モーションのうち1フレームへ切り替える。

すぐに元の立ち絵へ戻す。

- キャラクターのX・Yは変更しない。
- 攻撃モーション4枚をすべて再生しない。
- 専用の派手な攻撃エフェクトは不要。
- キャラの一瞬のポーズと、ピースの入れ替えTWEENは独立させる。

S1/S2のスプライトslot12～15から1枚を再利用できる。

具体的なslotと表示時間はテスト用調整値。

# 第5章　キャラクターの移動

## 5.1 横移動

キャラクターは現在選択している列の中心に立つ。

左右移動はTWEEN。

列ごとの中心X：

| 列 | 1P | 2P |
|---|---:|---:|
| 0 | 80 | 400 |
| 1 | 112 | 432 |
| 2 | 144 | 464 |
| 3 | 176 | 496 |
| 4 | 208 | 528 |
| 5 | 240 | 560 |

## 5.2 足元位置

キャラクターは、選択列の高さに応じて上下してはならない。

**そのプレイヤーのフィールド内で最も高い列の上端に、全列共通の足元Yを合わせる。**

列を移動しただけではキャラのYは変化しない。

フィールドの最高列が変化すると、全列共通の足元位置を再計算する。

## 5.3 表示フレーム

各キャラクターの画像枠は48×56。

モーションは待機、歩行、打ち上げ、攻撃、勝利、敗北。

位置移動のTWEENと、絵柄切り替えのFRAMEは区別する。

# 第6章　役ストック

## 6.1 基本仕様

- 各プレイヤー最大6個。
- 1個24×24。
- 数字と属性を両方表示。
- ストック表示は左詰め。
- 取得順に右側へ追加。

7個目取得時：

1. 左端の最古ピースを破棄。
2. 残り5個を左へ詰める。
3. 新しいピースを右端へ追加。

この処理は**SNAP**。

## 6.2 役宣言可能な個数

4個、5個、6個のいずれかで宣言できる。

4個の場合はその4個で評価。

5個の場合は5個から選べる4個の部分集合をすべて評価し、最も強いものを採択。

6個の場合は、成立する6個役のうち最も強いものを優先し、6個役がなければ4個の部分集合のうち最も強いものを採択。

数字役と属性役は、必ず**同一の採択部分集合**で評価する。

異なる部分集合で成立する数字役と属性役を寄せ集めてはいけない。

## 6.3 役宣言後

宣言すると、役の判定に採用しなかったピースも含め、**役ストック全体を消費する**。

取得済みピースを部分的に残す方式ではない。

## 6.4 役の重複

数字役と属性役は組み合わせ可能。

翻数を合算する。

属性役が複数成立する場合は、最も強い1種類のみを採用する。

属性役のみが成立する場合も有効とする。

複合役の名称は表示名であり、別の役として翻数を二重加算してはいけない。

# 第7章　役の種類と翻数

以下の翻数は過去設計から採用してきた値。ゲームロジックの入力資料として扱うが、攻撃ラインへの換算式とは別である。

## 7.1 数字役

| 役 | 条件 | 翻数 |
|---|---|---:|
| フォーカード | 同じ数字4個 | 1 |
| ニコニコ | 異なる数字のペア2組 | 1 |
| ストレート | 通常の4連番 | 1 |
| ハイストレート | 2・3・4・5 | 2 |
| フルカード | 同じ数字6個 | 3 |
| ニコニコニコ | 異なる数字の3個組が2組 | 3 |
| スーパーストレート | 1・2・3・4・5・6 | 3 |

通常の4連番の例は1234、3456。

2345は特別連番として2翻。

発射成功の数字1↔6隣接と、役の連番判定は別ルール。役判定で循環連番を勝手に追加しない。

## 7.2 属性役

| 役 | 条件 | 翻数 |
|---|---|---:|
| 同色統一 | すべて赤、またはすべて黒 | 1 |
| オールマーク | ♠♦♣♥の4属性をすべて含む | 2 |
| フラッシュ | すべて同じ属性 | 3 |

赤は♦♥、黒は♠♣。

同色統一は4個でも6個でも1翻。

## 7.3 複合役

数字役＋属性役の翻数を合計。

例：

- 通常ストレート1翻＋フラッシュ3翻＝4翻。
- ハイストレート2翻＋フラッシュ3翻＝5翻。
- 6連番3翻＋フラッシュ3翻＝6翻。

最後の6連番フラッシュの表示名は後述の暫定事項。

## 7.4 役の表示名

役名は通常フォントではなく、専用画像ロゴとして表示する。

| ID | ロゴ表記 |
|---|---|
| R01 | フォー\nカード！ |
| R02 | ニコ\nニコ！ |
| R03 | スト\nレート！ |
| R04 | ハイスト\nレート！ |
| R05 | フル\nカード！ |
| R06 | ニコニコ\nニコ！ |
| R07 | スーパースト\nレート！ |
| R08 | フォー\nブラック！ |
| R09 | フォー\nレッド！ |
| R10 | オール\nブラック！ |
| R11 | オール\nレッド！ |
| R12 | オール\nマーク！ |
| R13 | フラッ\nシュ！ |
| R14 | ストレート\nフラッシュ！ |
| R15 | ハイストレート\nフラッシュ！ |
| R16 | スーパーストレート\nフラッシュ！ |

注意：

- `\n`はロゴ造形で上下を大きく重ねるための指定。
- 普通の二行改行を意味しない。

## 7.5 役名演出

- 16種類。
- 各3フレーム。
- グラデーション色替えA/B/Cを循環。
- 一体型の重なりロゴ。
- キャラクターや役ストックとの重なりを許可。
- 各プレイヤーの中央寄り上部へ表示。

役名表示中は、**宣言したプレイヤーだけ操作不能**。

相手は通常どおり操作を続行する。

役名演出中、宣言側の自然上昇タイマーなど、停止対象のタイマーを適切に停止する。

# 第8章　取得速度・連鎖

## 8.1 連続取得

成功したピースの取得間隔を管理する。

過去の検討では、約2秒以内の連続成功を取得連続状態として扱う案がある。

打ち上げ失敗時は成功取得間隔タイマーを更新・リセットしない。

宣言後も連続取得状態を不必要に初期化しない。

過去の倍率案：

| 連続取得数 | 倍率 |
|---|---:|
| 1～2 | ×1.0 |
| 3～4 | ×1.5 |
| 5～6 | ×2.0 |
| 7以上 | ×2.5 |

この倍率テーブルは過去資料からの復元値であり、正式な確定範囲は次のWorkセッションで照合すること。

**得点倍率と攻撃倍率は異なる概念。混同禁止。**

## 8.2 役宣言連鎖

役宣言後、一定時間内に再度役を宣言すると連鎖する。

連鎖受付時間は約8秒が暫定案。

連鎖による追加攻撃ラインの案：

`bonus = min(chainCount - 1, 4)`

例：

- 1連鎖目：0ライン
- 2連鎖目：+1ライン
- 3連鎖目：+2ライン
- 4連鎖目：+3ライン
- 5連鎖目以降：+4ライン

自然上昇・手動上昇そのものは、役宣言連鎖を断ち切らない。

役演出中のタイマー停止を実装する。

連鎖ボーナスに取得速度倍率を重ねて掛けない。

連鎖時間、ボーナス計算、連続取得倍率の一部は過去決定の復元値であり、残る計算式の確定状況と併せて最終照合すること。

# 第9章　攻撃ストック

## 9.1 数値上限

各プレイヤーの攻撃待機ストックは最大29ライン。

表示上限だけでなく、**内部ロジック上の上限も29**。

30以上の攻撃を受け取っても、29に飽和する。

0へ戻したり、表示だけ29にしたりしない。

## 9.2 アイコン表示

- 大アイコン：10ライン、24×24。
- 小アイコン：1ライン、16×16。
- 大アイコン最大2個。
- 小アイコン最大9個。

小アイコンは**左列に先に5個縦積み、6個目から右列に4個**。

以前の設計資料で左4・右5となっている箇所は誤記。

15ラインなら大アイコン1個、その下の左列に小アイコン5個。

29ラインなら大2個＋小9個。

## 9.3 座標

1P攻撃表示起点：(256,128)。

2P攻撃表示起点：(352,128)。

大アイコンの縦ピッチは32px。

小アイコンの開始Yは：

`128 + 32 × bigCount`

小アイコン相対配置：

| 順番 | X | Y |
|---|---:|---:|
| 1 | 0 | 0 |
| 2 | 0 | 16 |
| 3 | 0 | 32 |
| 4 | 0 | 48 |
| 5 | 0 | 64 |
| 6 | 16 | 0 |
| 7 | 16 | 16 |
| 8 | 16 | 32 |
| 9 | 16 | 48 |

このXは各プレイヤーの表示起点からの相対値。

# 第10章　攻撃・相殺

## 10.1 攻撃波

蓄積した攻撃は一度に全量適用しない。

**最大3ラインずつ**段階的に適用する。

攻撃波の間隔は約2秒が暫定値。

この間隔はWAITであり、3ラインのピースが2秒かけて移動する意味ではない。

## 10.2 攻撃による行追加

攻撃で新しいピースを追加する場合、描画更新は**SNAP**。

自然・手動上昇がTWEENである点と区別する。

攻撃によって7段目までピースを押し込まない。

攻撃による盤面増加は最大6段まで。

入りきらない攻撃ストックは破棄せず、適用できるまで保持する。

## 10.3 役演出との競合

攻撃を受ける側が役宣言・攻撃モーション中なら、攻撃波の適用を待つ。

演出終了後に、攻撃ストックと盤面の空きを再評価する。

防御側が待機中でも、相手側のゲーム進行は停止しない。

## 10.4 相殺

相殺処理では、防御側の反撃による相殺力を通常攻撃力の2倍として扱う。

過剰になった相殺倍率分は攻撃へ転用しない。

例として、自分への攻撃待機量を打ち消せても、その余剰相殺力を自動的に相手への攻撃へ変換しない。

**未確定：**

- 役の翻数から通常攻撃ライン数への換算。
- ライン消去数と攻撃量の関係。
- 奇数ラインを相殺した場合の端数規則。
- 相殺と攻撃送信が同時に成立した場合の詳細順序。

これらを推測で正式確定してはならない。

# 第11章　自然上昇・手動上昇

## 11.1 自然上昇

フィールドは時間経過によって自然上昇する。

自然上昇のペースは試合の設定によって決まり、一定の速度を基本とする。

自然上昇による32pxの移動はTWEEN。

打ち上げ中のピースが存在しても、原則として自然上昇は進行する。

ただし、役宣言など停止対象の演出中は、そのプレイヤーの自然上昇を停止する。

## 11.2 手動上昇

プレイヤーの操作による手動上昇も32pxのTWEEN。

自然上昇とは別の入力イベントとして管理する。

手動上昇によって最大7段を超えてはならない。

## 11.3 攻撃上昇との違い

自然上昇：TWEEN。

手動上昇：TWEEN。

攻撃による行追加：SNAP。

これら3種類を、同じアニメーション処理だと決めつけてはならない。

## 11.4 危険状態と敗北

高さ7段が危険な状態。

そこからさらに自然上昇が発生する場合に、一度だけ短い猶予を与える案がある。

猶予は約3秒の暫定値。

猶予終了後も解消できず、次の上昇で8段目に達する場合に敗北。

勝敗判定の厳密な処理タイミングと猶予の開始・リセット条件は最終確定待ち。

# 第16章　イベント競合と操作制限

## 16.1 ロック階層

操作禁止には少なくとも2段階を設ける。

**プレイヤー全体ロック：**

役宣言・攻撃モーションなど、そのプレイヤーが操作不能になる演出。

**列単位ロック：**

打ち上げ失敗の帰還待ちなど、その列だけ再発射・B入れ替え不能になる状態。

相手プレイヤーや他列の操作を不必要に止めない。

## 16.2 非同期処理

複数の移動・演出が同時に存在しても、各ピースは一意のIDで追跡する。

ゲームロジック上の位置と、画面の表示位置を分離する。

描画FPSによって成功判定や勝敗が変化しないようにする。

共通基準への到達イベントは、到達フレームとプレイヤー優先順位で処理する。

## 16.3 同時上昇

帰還待ちの予約位置は、フィールドの上昇に追従する。

自然上昇と攻撃SNAPなどが重なっても、論理ピースが二重生成・消滅しないこと。

複数アニメーション間の描画座標合成は、ゲーム結果を変えない範囲で技術的に決定できる。

# 第17章　勝敗と試合進行

対戦は1P・2Pそれぞれ独立して盤面を操作し、共通基準へ打ち上げ、役宣言と攻撃を行う。

危険状態を超えてフィールドが溢れると敗北する。

ラウンド終了後は勝者を表示し、勝利数を更新する。

勝利数表示には3スロット分の枠を設ける。

ただし、**何勝先取でマッチ終了とするか**、引き分け発生条件、再戦操作の詳細は、正式な未確定事項として残す。

READY、GO、WIN、LOSE、COUNTER等のバナーを使用する。

中央の白猫マスコットはゲーム開始、勝敗、攻撃、連鎖などに応じた演出を行う。
